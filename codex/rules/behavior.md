# 行为规则

`AGENTS.md` 保存必须立即遵守的总原则；本文件只保留行为细则和执行口径。

## 证据优先

- **状态判断**：必须有工具输出证据，如编译结果、文件内容、git log。
- **代码引用**：必须读过文件确认存在，不编造行号、方法名、文件路径。
- **完成声明**：说“已修复”“已完成”前必须有对应验证结果。
- **内容生成**：改文件前先读当前内容，不能假设文件仍是上次看到的样子。

## 未重现问题

用户报告的问题如果本轮无法复现，不要硬改代码、配置或全局环境。正确处理方式：

1. 标记为“未重现”。
2. 记录复查命令、实际现象和环境信息。
3. 写清楚后续处理条件。
4. 只有稳定复现或有明确证据时才实施修复。

## 修改边界

- 只改完成目标必须改的内容，不顺手“优化”周围代码。
- 发现无关死代码或潜在问题，只记录或提示，不擅自删除。
- 需求不清先问；有歧义时给出理解差异和建议。
- 发现更简单方案可以主动提出，但要说明原因。

## 调研与局限

“做不到”是起点，不是终点。

- 无法验证 → 调研测试方案。
- 不熟悉 API → 查官方文档。
- 工具行为异常 → 先复现和定位，再决定是否修复。
- 调研结果有长期价值时，写入 `codex/rules/` 或 `docs/`。

## 规则沉淀

- 重复踩坑、框架反直觉行为、流程缺口，立刻写入对应规则文件。
- 必须执行的规则不能只写 memory；memory 不自动加载。
- 自定义命令、自动化脚本和规则模板不得包含无关项目硬编码。判断标准：换到另一个项目还能直接用。

## 文件编码

- UTF-8 无 BOM；行尾遵循仓库 `.gitattributes`。
- `.cmd` 脚本调用其他 `.cmd` 必须用 `call` 关键字。
