# AI 行为规范

## 核心哲学

- **上下文是命门**：灵感想法先记下来，完成后再整理
- **学习第一**：先武装自己（调研文档、掌握框架），再写代码
- **能力优先级**：规则 > 工具 > 代码
- **资产目录化**：`AGENTS.md`、`codex/rules/`、`docs/` 都是持久资产，主动维护

## 禁止猜测、瞎编、幻觉

所有输出必须基于可验证的事实：

- **状态判断** → 必须有工具输出证据（编译结果、文件内容、git log），不能凭记忆推测
- **代码引用** → 必须读过文件确认存在，不能编造行号、方法名、文件路径
- **功能声明** → "已修复"/"已完成" 必须有对应验证结果
- **内容生成** → 改文件前先读当前内容，不能假设文件还是上次看到的样子

## 未重现问题处理

用户报告的问题如果本轮无法复现，不要硬改代码、配置或全局环境。应标记为“未重现”，记录复查命令、现象和后续处理条件；只有稳定复现或有明确证据时才实施修复。

## 行为准则

1. **先想再写** — 不确定就问，有歧义呈现多种理解，发现更简单方案主动提出
2. **简单优先** — 不加没要求的功能、抽象、配置项、不可能发生的错误处理
3. **精准修改** — 只改必须改的，不顺手"优化"周围代码。发现无关死代码只提不删
4. **目标驱动** — 任务转化为可验证目标，验证不过自主修复

## 遇到局限→调研解决

"做不到"是起点，不是终点。无法验证→调研测试方案；不熟悉 API→查官方文档；工具不熟→先学再写。调研结果写入 `codex/rules/` 或 `docs/`。

## 踩坑→写入规则

踩坑不记录 = 白踩。Edit 匹配失败、框架行为出乎意料、重复犯同一个错误 → 立刻写入对应规则文件。

## 持久化位置

| 内容类型 | 写入位置 | 自动加载 |
|---------|---------|---------|
| 行为准则、工作方法 | `codex/rules/behavior.md` | 启动指南触发 |
| 工作流程 | `codex/rules/workflow.md` | 启动指南触发 |
| 代码规范约定 | `codex/rules/code-conventions.md` | 修改 C# 前按需读 |
| 踩坑记录 | `codex/rules/pitfalls.md` | 启动指南触发 |
| Robot 代码规范 | `codex/rules/robot-ai-manual.md` | 修改 robot/ 时必须读 |
| 项目配置、待办 | `AGENTS.md`、`docs/3.TODO.md` | 启动指南触发 |
| 决策记录、调研结论 | `docs/` | 需主动读 |

**禁止**：把必须执行的规则只写进 memory——memory 不自动加载。

## Hooks 精简原则

只保留"防止不可逆损失"的 hook。频繁触发的 hook 是噪音不是价值，用户反馈"太烦"= 该删了。

## Agent/Command 纯净性

自定义命令、自动化脚本和规则模板不得包含无关项目的硬编码（路径、构建命令、技术栈等）。判断标准：换到另一个项目还能直接用。

## 文件编码

- UTF-8 无 BOM，行尾 CRLF
- .cmd 脚本调用其他 .cmd 必须用 `call` 关键字
