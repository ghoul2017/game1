# 客户端逻辑层与表现层分离

## 概述

将客户端代码拆分为三个程序集：`Shared`（双端共享）→ `Logic`（纯 C# 客户端逻辑，零 Unity 依赖）→ `View`（Unity 渲染/UI/交互）。

分离后 Robot 可直接引用 Shared + Logic 完成自动化测试。

## 当前问题

- 所有客户端代码编译为单一 `Assembly-CSharp.dll`，无程序集边界
- Handler 类（纯逻辑）通过 `UIManager.Instance?.GetPanel<T>()` 直接耦合 Unity UI
- 无 `.asmdef` 文件，无法控制程序集依赖

## 目标架构

```
Shared (netstandard2.0)
  ↑
Logic (netstandard2.0, 零 UnityEngine 引用)
  ↑
View  (Unity 程序集, 通过 .asmdef 约束)
```

### Shared 程序集
- 内容：`client/Assets/Scripts/Shared/` 全部文件（已纯 C#）
- 无变更，创建 `.asmdef` + 独立 `.csproj` 供 Robot 引用

### Logic 程序集
- 内容：Handler 类 + 数据类 + IClientUI 接口
- **零 UnityEngine 引用**
- 创建 `.asmdef`（Unity 内编译）+ `.csproj`（Robot 引用）

### View 程序集
- 内容：Panel、View、NetClient、GameSceneEntry 等 UnityEngine 依赖代码
- 引用 Shared + Logic
- 启动时设置 `Logic.ClientContext.UI = UIManager.Instance`

```csharp
{
    public interface IClientUI
    {
        T GetPanel<T>() where T : class;
        void ShowPanel<T>() where T : class;
        void HidePanel<T>() where T : class;
        void ReplacePanel<T>() where T : class;
        void ClearAll();
        void Back();
        void ShowToast(string msg);
        void ShowMessageBox(string title, string content, Action onOk, Action onCancel);
    }

    public static class ClientContext
    {
        public static IClientUI UI { get; set; }
    }
}
```

## 执行顺序

1. 创建 `Shared.asmdef` + `Shared.csproj`
2. 创建 `Logic/IClientUI.cs` + `ClientContext` + `Logic.asmdef` + `Logic.csproj`
3. 迁移 `GameData.cs`、`MapData.cs`、`MapObjectType.cs` 到 `Logic/`
4. 逐个迁移 Handler 类到 `Logic/`，替换 `UIManager.Instance` → `ClientContext.UI`
5. 创建 `View.asmdef`
6. 迁移所有 Panel/View/NetClient/Core 到 `View/`
7. 在 `GameEntry.cs` 中添加 `ClientContext.UI = UIManager.Instance;`
8. 在 Unity Editor 中刷新程序集，验证编译
9. `dotnet build game1.sln` 通过
10. `dotnet build shared/Shared.csproj` 通过
11. `dotnet build client/Assets/Scripts/Logic/Logic.csproj` 通过
