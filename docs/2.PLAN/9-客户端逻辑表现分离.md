# 客户端逻辑层与表现层分离

## 概述

将客户端代码拆分为三个目录：`Shared`（双端共享）→ `Logic`（纯 C# 客户端逻辑，零 Unity 依赖）→ `View`（Unity 渲染/UI/交互）。无 .asmdef 程序集隔离，Robot 通过 Compile Include 直接引用 Shared + Logic 源文件。

分离后 Robot 可直接引用 Shared + Logic 完成自动化测试。

## 当前问题

- 所有客户端代码编译为单一 `Assembly-CSharp.dll`，无程序集边界
- Handler 类（纯逻辑）通过 `UIManager.Instance?.GetPanel<T>()` 直接耦合 Unity UI

## 目标架构（实际实施：纯目录分离，无 .asmdef）

```
Shared/（双端共享代码，纯 C#）
  ↑ Compile Include
Logic/（零 UnityEngine 引用，纯 C#）
  ↑ Compile Include
Robot.csproj（net8.0 Console，引用上述两个目录的源文件）
```

### Shared 目录
- 内容：`client/Assets/Scripts/Shared/` 全部文件（已纯 C#）
- 无变更，Robot 通过 Compile Include 引用

### Logic 目录
- 内容：Handler 类 + 数据类 + IClientUI 接口
- **零 UnityEngine 引用**
- Robot 通过 Compile Include 引用

### View 目录
- 内容：Panel、View、NetClient、GameSceneEntry 等 UnityEngine 依赖代码
- 启动时设置 `Logic.ClientContext.UI = UIManager.Instance`
