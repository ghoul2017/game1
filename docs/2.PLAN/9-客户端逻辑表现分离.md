# 客户端逻辑层与表现层分离（第二次重构）

## 概述

第一次重构创建了 Logic/View 目录分离和 IPanel 接口模式，但用户反馈未满足需求：
1. View 面板仍持有业务状态（背包物品列表、邮件列表、任务列表、聊天记录等）
2. View 面板直接调用 `NetClient.Instance.Send()` 发送网络消息
3. Logic Handlers 只是薄透传层，调用 `ClientContext.UI?.GetPanel<T>().HandleXxx()` 而不处理数据
4. View 目录中存在非表现代码（NetClient.cs / Context.cs / MapData.cs）

## 第二次重构：Controller 模式

### 架构变更

```
之前：Handler → IPanel.HandleXxx() → Panel（持有状态 + 发消息 + 做决策）
之后：Handler → Controller（持有状态 + 业务逻辑）→ 事件 → Panel（纯渲染 + 订阅刷新）
```

依赖方向：`Shared ← Logic ← View`

### 核心变更清单

1. **8 个 Controller**（Logic/Controllers/）：Login / RoleSelect / Bag / Mail / Task / Chat / Fight / Map
2. **NetClient 移到 Logic**：去掉 MonoBehaviour，改为纯 C# 类，GameEntry.Update 驱动
3. **Context.cs 移到 Logic**：零 UnityEngine 引用，纯逻辑
4. **MapData.cs 移到 Logic**：去掉 Vector3 依赖，返回 (float,float,float) 元组
5. **INetworkSender 接口**：Logic 层通过 `ClientContext.Network?.Send(msg)` 发消息，不依赖 View
6. **MapHandlers.cs**：从 GameSceneEntry 迁出 9 个 `[MessageHandler]` 到 Logic
7. **IPanels.cs 简化**：移除所有 `HandleXxx` 方法签名，保留空标记接口

### Controller 设计约定

- 单例模式：`public static XxxController Instance { get; } = new();`
- 状态：public get / private set 属性
- Action：public 方法，供 View Panel 调用
- 事件：`event Action` / `event Action<T>`，Panel 在 OnShow 订阅、OnHide 取消
- 消息发送：`ClientContext.Network?.Send(msg)`
- Toast 提示：`ClientContext.UI?.ShowToast(msg)`

### 关键决策

1. **不用 EventBus**：用 `event Action` 减少文件数量
2. **LoginController 连接桥接**：BeginLogin() 返回 NeedConnect 时，LoginPanel 负责调 NetClient.Connect()
3. **ConfigManager 查询保留在 View**：物品品质颜色等是"显示格式化"
4. **战斗视觉效果保留在 View**：伤害数字、死亡动画等是渲染逻辑
5. **IPanels.cs 不删除**：保留空标记接口，保持 `UIManager.GetPanel<T>()` 类型参数模式
