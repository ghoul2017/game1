# 字符串消息名协议

## 目标

将协议路由从人工维护的 `ushort MsgId` 改为显式字符串消息名，降低新增协议时的 ID 分配、冲突和漏改成本。

新包格式：

```text
[FrameLength:4B][NameLength:2B][Name:UTF8][Payload]
```

- `FrameLength`：后续帧长度，不包含自身 4 字节。
- `NameLength`：消息名 UTF-8 字节长度。
- `Name`：稳定协议名，不从类名自动推导。
- `Payload`：protobuf-net 序列化数据。

消息名格式：

```csharp
[Message("User.LoginReq")]
public sealed class LoginReq : IMessage
{
}
```

## 修改范围

- `client/Assets/Scripts/shared/Core/Network/`
- `client/Assets/Scripts/shared/Common/Protos/`
- `client/Assets/Scripts/Logic/`
- `server/Core/Network/`
- `server/Components/*/*Handlers.cs`
- `robot/`
- `docs/line-kb/protocol-config.md`

## 实施步骤

1. 新增 `MessageAttribute` 和 `MessageRegistry`
   - `MessageAttribute` 保存稳定消息名。
   - `MessageRegistry` 扫描 `IMessage` 类型，建立 `name -> Type`、`Type -> name`。
   - 启动校验缺失消息名、重复消息名、空消息名。

2. 改造消息接口和协议类
   - `IMessage` 改为纯标记接口或只保留序列化扩展所需成员。
   - 所有 `*Req`、`*Res`、`*Ack`、`*Ntf` 加 `[Message("模块.消息名")]`。
   - 不再新增或使用 `MsgIdConst`。

3. 改造 `PacketCodec`
   - `Encode(string messageName, byte[] payload)`。
   - 解码结果返回 `MessageName`、`Payload`、`Consumed`。
   - 粘包和半包判断统一以 `FrameLength` 为准。

4. 改造发送和接收链路
   - `TcpSession.Send(IMessage msg)` 通过 `MessageRegistry` 获取消息名。
   - 接收后通过消息名反查类型，再用 protobuf-net 反序列化。
   - 未注册消息名直接记录错误并断开或丢弃，具体行为按现有网络错误处理保持一致。

5. 改造 `MessageRouter`
   - Handler 字典从 `Dictionary<ushort, IMessageHandler>` 改为 `Dictionary<string, IMessageHandler>`。
   - 扫描 Handler 时从请求参数类型读取 `[Message]`。
   - 重复 Handler、请求类型未注册时启动失败。

6. 同步客户端、服务端和 Robot
   - 客户端请求、通知 Handler 和日志从 `MsgId` 改为 `MessageName`。
   - 服务端 Handler 注册、响应、通知发送同步修改。
   - Robot 发送、接收分发和日志同步修改。

7. 删除旧 MsgId 入口
   - 删除 `MsgIdConst`。
   - 全仓库搜索 `MsgIdConst`、`.MsgId`、`ReqMsgId`，清理残留引用。

## 验证

- `dotnet build game1.sln`
- Robot 至少覆盖：
  - 登录
  - 创建或进入角色
  - 进入地图
  - 背包查询
  - 任一通知类消息
- 协议一致性检查通过：
  - 所有 `IMessage` 类型有 `[Message]`
  - 消息名不重复
  - Handler 请求类型已注册
  - 旧 `MsgIdConst` 无残留引用

## 风险

- 这是协议级迁移，应一次完成，不长期保留 `MsgId` 和 `MessageName` 双轨。
- 消息名是对外协议，不随类名重命名自动变化。
- 字符串包头比 `ushort` 更大，当前阶段可接受；若后续需要压缩，可在消息名协议稳定后再生成短码表。
