## 2. 环境准备

### 2.1 必要依赖

- Unity 2022.3.62f3c1，用于打开 `client/` 并进入 PlayMode；版本权威文件为 `client/ProjectSettings/ProjectVersion.txt`。
- .NET 8 SDK，用于构建和运行 `server/`、`robot/`、`tools/`。
- MongoDB，默认连接 `mongodb://127.0.0.1:27017`，数据库名 `game`。
- 服务端端口默认 `9000`；源配置为 `server/appsettings.json`，构建后复制为 `bin/appsettings.json`。

### 2.2 启动服务端

仓库根 `Directory.Build.props` 将 .NET 输出统一到 `bin/`；`server/Server.csproj` 会把 `appsettings.json` 和客户端唯一配置源 `client/Assets/StreamingAssets/Tables/*.csv` 复制到该目录。先构建，再以 `bin/` 为工作目录运行输出程序集：

```bash
dotnet build server/Server.csproj
cd bin
dotnet Server.dll
```

预期现象：

- MongoDB 初始化成功，日志包含“数据库模块初始化完成”。
- 配置表加载成功，日志包含 `Map.csv`、`Monster.csv`、`Skill.csv`、`Task.csv` 等加载记录。
- 地图初始化成功，日志包含“默认地图初始化完成”。
- 网络监听成功，日志包含“监听 0.0.0.0:9000”。

Rider 直接调试 `bin/Server` 时使用同一套输出配置和 `bin/Data/Tables`。服务端只从构建后的 `bin/` 目录运行；不要用 `dotnet run --project server/Server.csproj` 启动，因为程序按当前工作目录解析配置和表的相对路径。

### 2.3 启动客户端

1. Unity Editor 打开仓库内的 `client/`。
2. 确认服务端已启动。
3. 点击 Play。

预期现象：

- `GameEntry` 初始化配置、客户端上下文、UIManager 和 NetworkStatusPanel。
- 界面显示 `LoadingPanel`，随后进入 `LoginPanel`。
- 登录后流程为 `RoleSelectPanel` → 游戏场景 → `MainPanel`。

### 2.4 日志位置

| 来源 | 查看方式 |
|------|----------|
| 服务端控制台 | 启动服务端的终端 |
| 服务端文件日志 | `bin/log/*.log` |
| Unity 日志 | Editor Console |
| Robot 日志 | 运行 Robot 的终端 |

### 4.2 当前未自动化但适合补 Robot 的场景

| 场景 | 建议消息序列 | 主要断言 |

## 5. 手工测试主流程

### ENV-01 服务端启动

前置条件：MongoDB 已启动。

步骤：

1. 构建服务端，从 `bin/` 目录启动 `dotnet Server.dll`。
2. 观察终端和 `bin/log/`。

预期：

- 服务端不退出。
- 配置、数据库、事件、地图、网络均初始化完成。
- 监听 `0.0.0.0:9000`。

### ENV-02 客户端启动

前置条件：服务端已启动。

步骤：

1. Unity 打开 `client/`。
2. 点击 Play。

预期：

- 无编译错误。
- 初始显示登录界面。
- 网络状态面板可显示连接状态和 Ping。

### NET-01 握手和心跳

步骤：

1. 在登录界面输入有效账号密码并点击登录。
2. 等待进入角色选择界面。
3. 保持在线超过 30 秒。

预期：

- 登录过程中客户端先建立 TCP，再发送 `HandshakeReq`。
- 服务端 `HandshakeReqHandler` 记录 Session。
- 客户端每 30 秒发送 `HeartbeatReq`。
- 服务端每 20 秒检查一次超时连接，60 秒未活跃连接会被断开。

### USER-01 正常登录和自动注册

步骤：

1. 输入新账号，例如 `qa_0608_001`。
2. 输入密码，例如 `123456`。
3. 点击登录。

预期：

- 首次登录自动注册账号。
- 客户端进入角色选择界面。
- `LoginRes` 包含 `PlayerId`、`Token` 和角色列表。

### USER-02 登录输入校验

| 步骤 | 预期 |
|------|------|
| 账号为空，点击登录 | 客户端提示 `请输入账号` |
| 密码为空，点击登录 | 客户端提示 `请输入密码` |
| 已存在账号使用错误密码 | 服务端返回 `密码错误` |

### USER-03 重复登录顶号

前置条件：准备两个客户端实例或一个 Unity 客户端加一个 Robot/临时客户端。

步骤：

1. 客户端 A 用账号 `qa_same` 登录并进入角色选择或游戏。
2. 客户端 B 用同一账号 `qa_same` 登录。

预期：

- 服务端对旧 Session 发送 `KickNtf` 并断开旧连接。
- 如果客户端 A 已在游戏场景内，会显示被迫下线提示；若仍停留在角色选择界面，当前代码未看到独立提示 Handler，应以断开连接和服务端日志作为判定。
- 客户端 B 登录成功。

### ROLE-01 角色列表

步骤：

1. 使用新账号登录。
2. 进入角色选择界面。

预期：

- 显示 4 个角色槽位。
- 新账号显示空槽位，已有角色显示角色名、等级和职业。
- 底部进入游戏按钮在未选中角色时不可用。

### ROLE-02 创建角色成功

步骤：

1. 点击空角色槽。
2. 输入 1-12 字符角色名。
3. 选择职业。
4. 点击确认创建。

预期：

- 成功后关闭创建弹窗。
- 新角色加入列表并被选中。
- 角色数量显示更新为 `已有角色 (n/4)`。

### ROLE-03 创建角色失败

| 步骤 | 预期 |
|------|------|
| 名称为空 | 客户端提示 `请输入角色名称` |
| 名称超过 12 字符 | 客户端提示 `角色名称最多12个字符` |
| 使用已有角色名 | 服务端返回 `角色名已存在` |
| 同账号已有 4 个角色后继续创建 | 服务端返回 `最多创建4个角色` |
| 未登录状态直接发 `CreateRoleReq` | 服务端返回 `未登录` |

### ROLE-04 进入游戏

步骤：

1. 选中已有角色。
2. 点击进入游戏。

预期：

- 客户端发送 `EnterGameReq`。
- 服务端先完成 `PlayerOnlineEvent` 级联加载，再发送 `EnterGameNtf`。
- 客户端随后发送 `EnterMapReq`。
- 最终进入游戏场景并显示 `MainPanel`。

## 7. 怪物和战斗

### FIGHT-01 选中目标

步骤：

1. 在新手村靠近怪物。
2. 鼠标点击怪物模型。

预期：

- 客户端设置 `GameData.SelectedTargetId`。
- 主界面目标栏显示目标。
- Unity Console 输出选中怪物日志。

### FIGHT-02 普通攻击

前置条件：已选中怪物，且距离在技能范围内。

步骤：

1. 点击右下角“普攻”按钮，或按键盘 `1`。

预期：

- 客户端发送 `UseSkillReq(SkillId=1, TargetId=目标)`。
- 服务端校验攻击者、技能、目标、距离和 CD。
- 成功后攻击者收到 `UseSkillAck`。
- 目标 HP 降低，视野内对象收到技能效果或 HP 变化通知。

### FIGHT-03 技能异常

| 步骤 | 预期错误 |
|------|----------|

| 攻击已死亡目标 | `目标已死亡` |

步骤：

1. 点击主界面右上区域 PK 模式按钮。
2. 连续点击 4 次。

预期：

- 客户端按 `和平 → 组队 → 帮派 → 全体 → 和平` 循环。
- 每次发送 `SetPkModeReq` 并收到 `PkModeChangedNtf`。
- 当前实现只回传模式，不做额外战斗规则校验。

### FIGHT-05 怪物死亡和掉落

步骤：

1. 攻击怪物直到死亡。
2. 观察怪物消失、奖励和任务进度。

预期：

- Fight 检测 HP 小于等于 0 后调用地图怪物死亡流程。
- 地图移除怪物并通过 AOI 通知客户端。
- 根据怪物配置发放经验、金币和掉落物品。
- 发布 `MonsterKilledEvent`，可驱动任务击杀进度。
- 怪物到刷新时间后重新生成。

预期：

### BAG-03 使用消耗品（功能未完成）

前置条件：背包中有 `2001-2999` 范围内消耗品。

当前只保留了请求、扣除和部分效果处理骨架，不作为已实现功能验收。完成独立功能任务后再执行以下用例。

步骤：

1. 点击有物品的格子。
2. 在确认框中确认使用。

预期：

- 客户端发送 `BagUseItemReq(Index, Count=1)`。
- 非消耗品返回 `物品使用失败`。
- 物品不存在返回 `物品不存在`。
- 数量不足返回 `物品数量不足`。
- 消耗品成功时按已确认的请求数量语义扣减物品，并显示 `使用了 <物品名>`。
- HP/MP/复活效果与物品扣除次数一致；效果配置缺失或语义未确认时不得只扣物品后返回成功。

### BAG-04 背包交换协议

当前服务端支持 `BagSwapReq(Index1, Index2)`，但 `BagPanel` 没有拖拽交换 UI。此项应通过 Robot 或临时协议客户端测试：

1. 预置两个不同格子物品。
2. 发送 `BagSwapReq`。
3. 再发送 `QueryBagReq`。

预期：两个格子的物品 Index 交换，Ack 无错误。

## 11. 任务

### TASK-01 查询任务

步骤：

1. 进入游戏。
2. 点击主界面左侧“任务”。

预期：

- 客户端发送 `QueryTaskListReq`。
- 新角色首次上线时服务端创建任务组件。
- 任务列表显示当前已接取任务数量。

### TASK-02 接取任务

步骤：

1. 在任务面板输入 `1`。
2. 点击“接取”。

预期：

- 客户端发送 `TaskAcceptReq(TaskId=1)`。
- 成功后列表新增任务。
- Toast 显示 `接取任务成功`。
- 重复接取同一任务返回 `任务已接取`。
- 内存立即出现任务；断线触发批量保存后，MongoDB `role_task_component.Tasks` 为数组并包含任务 1。
- 重新登录并进入游戏后返回相同 `AcceptTime`。这验证的是持久化恢复，不是 `ReconnectReq` 协议。

### TASK-03 接取输入校验

| 步骤 | 预期 |
|------|------|
| 输入为空 | Toast：`请输入任务ID` |
| 输入非数字或小于等于 0 | Toast：`无效的任务ID` |
| 输入不存在的任务 ID | 服务端返回 `任务不存在` |
| 已有 20 个进行中任务后继续接取 | 服务端返回 `任务列表已满` |

### TASK-04 任务进度

前置条件：已接取任务 1。

步骤：

1. 击杀 `CfgId=101` 的野猪。
2. 重复直到任务目标完成。

预期：

- 怪物死亡发布 `MonsterKilledEvent`。
- 任务目标 `击杀怪物 101` 进度递增。
- 内存进度变化后立即推送任务变化并标脏；断线批次保存后重新登录，`CurrentCount` 保持一致。
- 达成目标后任务状态变为 `可提交`。
- 客户端收到 `TaskChangedNtf` 并刷新任务面板。

### TASK-05 提交和放弃

| 场景 | 步骤 | 预期 |
|------|------|------|
| 提交未完成任务 | 选中进行中任务，点击提交 | 服务端返回 `任务未完成` |
| 放弃进行中任务 | 选中进行中任务，点击放弃并确认 | 任务从列表移除，Toast：`已放弃任务` |
| 放弃已完成任务 | 完成任务后点击放弃 | 服务端返回 `任务已完成` |
| 提交已完成任务 | 完成任务后点击提交 | 任务进入已领奖状态，客户端列表移除，奖励物品进入背包 |
| 重复提交任务 | 领奖后再次发送同一提交请求 | 返回 `任务已提交`，背包奖励不重复增加 |
| 领奖后重新登录 | 完成提交后断线并重新登录 | 任务状态为 2，奖励总数与提交完成后一致 |

野猪 101 可能随机掉落 `1001`，自动化判断任务奖励时应断言提交前后数量增加 1，不能断言背包内 `1001` 总数恰好为 1。任务与背包分集合批量保存，当前不验证跨集合原子性。

当前已接入事件驱动的目标类型：击杀怪物、收集物品、达到等级。对话 NPC、进入场景、使用物品、击杀玩家、通关副本目标类型已有定义但未接入驱动。

## 13. 断线重连

### NET-02 自动重连

前置条件：角色已进入游戏。

步骤：

1. 临时停止服务端或断开网络。
2. 观察客户端网络状态。
3. 在重试次数耗尽前恢复服务端或网络。

预期：

- 客户端最多重连 5 次。
- 重连延迟按 `1s, 2s, 4s, 8s, 16s` 递增，上限 30 秒。
- 握手成功后，如果 `GameData.Token` 和当前角色存在，会发送 `ReconnectReq`。
- 重连成功后发送 `EnterGameReq` 恢复角色在线状态。
- 成功发布 `NetReconnectedEvent`，失败发布 `NetReconnectFailedEvent`。

### NET-03 重连失败

步骤：

1. 进入游戏后断开网络。
2. 等待 5 次重连全部失败。

预期：

- 客户端进入断开状态。
- 游戏场景内收到 `MapReconnectFailedEvent` 后清理其他玩家并加载回 `SampleScene`；Unity Console 输出重连失败日志。

## 14. 当前限制和测试注意事项

- Robot 当前覆盖登录和任务持久化；背包、邮件、聊天、AOI 和 `ReconnectReq` 协议仍需新增场景。
- 邮件正向流程没有内置触发入口，需要预置邮件或补测试工具。
- 聊天 UI 当前没有私聊目标输入框，正向私聊只能通过协议测试。
- 背包服务端容量是 100，`BagPanel` 当前只绘制 64 个可见格子。
- 服务端有 `BagSwapReq`，但当前背包 UI 没有交换操作入口。
- 道具使用功能尚未完成：效果配置关联和请求数量语义都需在独立功能任务中补齐，当前不作为已实现功能验收。
- 任务配置中的前置任务、最低等级、经验和金币奖励字段当前没有完整接入提交发奖流程；提交主要发放 `RewardItems`。
- 怪物 AI 已知局限包括单目标仇恨、随机巡逻、攻击后回 Idle、无脱战回血。
- 地图移动当前只做边界限制，没有碰撞和寻路。
- 密码当前明文存储，仅适合内网测试环境。
