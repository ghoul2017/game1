## 2. 环境准备

### 2.1 必要依赖

- Unity 2022.3.62f3c1，用于打开 `client/` 并进入 PlayMode；版本权威文件为 `client/ProjectSettings/ProjectVersion.txt`。
- .NET 8 SDK，用于构建和运行 `server/`、`robot/`、`tools/`。
- MongoDB，默认连接 `mongodb://127.0.0.1:27017`，数据库名 `game`。
- 服务端端口默认 `9000`；源配置为 `server/appsettings.json`，构建后复制为 `bin/appsettings.json`。

### 2.2 启动服务端

仓库根 `Directory.Build.props` 将 .NET 输出统一到 `bin/`；`server/Server.csproj` 会把 `appsettings.json` 和客户端唯一配置源 `client/Assets/StreamingAssets/Tables/*.csv` 复制到该目录。先构建，再以 `bin/` 为工作目录运行输出程序集：

```bash
dotnet build server/Server.csproj
cd bin
dotnet Server.dll
```

预期现象：

- MongoDB 初始化成功，日志包含“数据库模块初始化完成”。
- 配置表加载成功，日志包含 `Map.csv`、`Monster.csv`、`Skill.csv`、`Task.csv` 等加载记录。
- 地图初始化成功，日志包含“默认地图初始化完成”。
- 网络监听成功，日志包含“监听 0.0.0.0:9000”。

Rider 直接调试 `bin/Server` 时使用同一套输出配置和 `bin/Data/Tables`。服务端只从构建后的 `bin/` 目录运行；不要用 `dotnet run --project server/Server.csproj` 启动，因为程序按当前工作目录解析配置和表的相对路径。

### 2.3 启动客户端

1. Unity Editor 打开仓库内的 `client/`。
2. 确认服务端已启动。
3. 点击 Play。

预期现象：

- `GameEntry` 初始化配置、客户端上下文、UIManager 和 NetworkStatusPanel。
- 界面显示 `LoadingPanel`，随后进入 `LoginPanel`。
- 当前默认在线流程为 `RoleSelectPanel` → `OnlineExpeditionGameplayView`；不会切换旧 `GameScene/MainPanel`。

### 2.4 日志位置

| 来源 | 查看方式 |
|------|----------|
| 服务端控制台 | 启动服务端的终端 |
| 服务端文件日志 | `bin/log/*.log` |
| Unity 日志 | Editor Console |
| Robot 日志 | 运行 Robot 的终端 |

### 2.5 本机在线技术版本

前置：MongoDB 正在监听 `127.0.0.1:27017`，Unity 使用 `2022.3.62f3c1` 打开 `client/`。

1. 选择 `Tools/Online Technical/Build, Start Server and Play`。
2. 等窗口确认所需 .NET SDK、MongoDB 与 `127.0.0.1:9000`，等待自动打开 `OnlineTechnicalScene` 并 Play。
3. 登录；没有账号时会自动注册。创建或选择角色后应直接出现在线远征世界，而不是旧 RPG 地图。
4. 持续按住 WASD/方向键或拖住触摸摇杆移动；观察队伍、敌人、资源、房门、路线和 Boss 危险圈随权威快照
   更新。队伍不应按约 200 ms 快照周期向后跳；松手、撞到房间边界或切换房间时允许回到权威位置。
5. 完成终局，执行唯一结算，回基地升级训练设施，再开始第二局；第二局代表伤害应提高。
6. 展开“在线诊断面板”可执行 Arena 开始、回放、1 倍、4 倍和跳过；诊断抽屉不应遮挡主玩法。
7. 用 `Tools/Online Technical/Stop Local Server` 停服，或退出 Unity；确认服务端优雅保存且 9000 不再监听。

常见阻断：缺少 `global.json` 指定 SDK、27017 不可连接、9000 被未知进程占用或目标场景有未保存修改。工具不会
自动启动 MongoDB，不会接管未知监听者，也不会把服务端能力打入 Player。

## 4. 自动化冒烟测试

### 4.1 当前已有 Robot 覆盖

当前 `robot/Program.cs` 注册了四个场景；不传 `--scenario` 时只运行前两个默认安全场景：

- `login_test`：使用账号 `test`、密码 `123456` 验证握手、登录、`PlayerId`、Token 和角色列表。
- `task_persistence_test`：每次使用独立的 `robot_task_<时间戳>` 账号和角色，验证任务 1 的接取、重复错误、断线批次保存、重新登录、5 次击杀进度、提交奖励和重复提交；同时校验 Uid 背包快照、一次 AddItems 只推送一次最终变化，以及未实现的按 Uid 使用不会扣物品。
- `expedition_authority_test`：显式运行；创建时间戳账号，覆盖远征 Start 幂等/冲突、伪造拒绝、断线恢复、
  自动终局、结算、升级和第二局。
- `arena_idempotency_test`：显式运行；创建时间戳账号，覆盖 Arena RequestId 幂等、固定摘要与回放。

执行步骤：

```bash
dotnet build robot/Robot.csproj
```

另开终端启动服务端：

```bash
cd bin
dotnet Server.dll
```

回到仓库根目录运行 Robot：

```bash
dotnet run --project robot/Robot.csproj
```

或只运行指定场景：

```bash
dotnet run --project robot/Robot.csproj -- --scenario login_test
dotnet run --project robot/Robot.csproj -- --scenario task_persistence_test
dotnet run --project robot/Robot.csproj -- --scenario expedition_authority_test
dotnet run --project robot/Robot.csproj -- --scenario arena_idempotency_test
```

预期结果：

- 输出 `PASS: login_test`。
- 单独执行任务场景时输出 `PASS: task_persistence_test`；它会创建一组测试账号/角色数据并击杀 5 只测试怪物。
- 单独执行远征/Arena 时分别输出 `PASS: expedition_authority_test`、`PASS: arena_idempotency_test`；二者会创建
  MongoDB 测试数据，必须显式选择。
- 单场景汇总为 `=== 完成: 1 通过, 0 失败 ===`；不传 `--scenario` 时应汇总 2 个场景。
- 服务端有对应握手和登录日志。

### 4.2 当前未自动化但适合补 Robot 的场景

| 场景 | 建议消息序列 | 主要断言 |
|------|--------------|----------|
| 创建角色 | `HandshakeReq` → `LoginReq` → `CreateRoleReq` | 成功返回 `CreateRoleRes.Role`，重复名返回 `角色名已存在` |
| 背包容量边界 | 预置 99、100、101 栈后分别查询并触发任务/掉落 | 100 栈仍可完整领取批次，101 栈时任务拒绝而掉落仍完整添加 |

| 世界聊天 | 两个 Robot 登录进入游戏后 `ChatReq(Channel=1)` | 发送者和接收者收到 `ChatNtf`，3 秒内第二条返回冷却错误 |
| 私聊 | 两个 Robot 登录进入游戏后 `ChatReq(Channel=3, TargetName=目标名)` | 目标在线时收到 `ChatNtf`，目标为空/自己/离线时返回错误 |
| 地图切换 | 进入游戏后 `ChangeMapReq` | Ack 坐标为目标地图出生点，并收到 `EnterMapNtf` |

## 5. 手工测试主流程

### ENV-01 服务端启动

前置条件：MongoDB 已启动。

步骤：

1. 构建服务端，从 `bin/` 目录启动 `dotnet Server.dll`。
2. 观察终端和 `bin/log/`。

预期：

- 服务端不退出。
- 配置、数据库、事件、地图、网络均初始化完成。
- 监听 `0.0.0.0:9000`。

### ENV-02 客户端启动

前置条件：服务端已启动。

步骤：

1. Unity 打开 `client/`。
2. 点击 Play。

预期：

- 无编译错误。
- 初始显示登录界面。
- 网络状态面板可显示连接状态和 Ping。

### NET-01 握手和心跳

步骤：

1. 在登录界面输入有效账号密码并点击登录。
2. 等待进入角色选择界面。
3. 保持在线超过 30 秒。

预期：

- 登录过程中客户端先建立 TCP，再发送 `HandshakeReq`。
- 服务端 `HandshakeReqHandler` 记录 Session。
- 客户端每 30 秒发送 `HeartbeatReq`。
- 服务端每 20 秒检查一次超时连接，60 秒未活跃连接会被断开。

### USER-01 正常登录和自动注册

步骤：

1. 输入新账号，例如 `qa_0608_001`。
2. 输入密码，例如 `123456`。
3. 点击登录。

预期：

- 首次登录自动注册账号。
- 客户端进入角色选择界面。
- `LoginRes` 包含 `PlayerId`、`Token` 和角色列表。

### USER-02 登录输入校验

| 步骤 | 预期 |
|------|------|
| 账号为空，点击登录 | 客户端提示 `请输入账号` |
| 密码为空，点击登录 | 客户端提示 `请输入密码` |
| 已存在账号使用错误密码 | 服务端返回 `密码错误` |

### USER-03 重复登录顶号

前置条件：准备两个客户端实例或一个 Unity 客户端加一个 Robot/临时客户端。

步骤：

1. 客户端 A 用账号 `qa_same` 登录并进入角色选择或游戏。
2. 客户端 B 用同一账号 `qa_same` 登录。

预期：

- 服务端对旧 Session 发送 `KickNtf` 并断开旧连接。
- 如果客户端 A 已在游戏场景内，会显示被迫下线提示；若仍停留在角色选择界面，当前代码未看到独立提示 Handler，应以断开连接和服务端日志作为判定。
- 客户端 B 登录成功。

### ROLE-01 角色列表

步骤：

1. 使用新账号登录。
2. 进入角色选择界面。

预期：

- 显示 4 个角色槽位。
- 新账号显示空槽位，已有角色显示角色名、等级和职业。
- 底部进入游戏按钮在未选中角色时不可用。

### ROLE-02 创建角色成功

步骤：

1. 点击空角色槽。
2. 输入 1-12 字符角色名。
3. 选择职业。
4. 点击确认创建。

预期：

- 成功后关闭创建弹窗。
- 新角色加入列表并被选中。
- 角色数量显示更新为 `已有角色 (n/4)`。

### ROLE-03 创建角色失败

| 步骤 | 预期 |
|------|------|
| 名称为空 | 客户端提示 `请输入角色名称` |
| 名称超过 12 字符 | 客户端提示 `角色名称最多12个字符` |
| 使用已有角色名 | 服务端返回 `角色名已存在` |
| 同账号已有 4 个角色后继续创建 | 服务端返回 `最多创建4个角色` |
| 未登录状态直接发 `CreateRoleReq` | 服务端返回 `未登录` |

### ROLE-04 进入游戏

步骤：

1. 选中已有角色。
2. 点击进入游戏。

预期：

- 客户端发送 `EnterGameReq`。
- 服务端先完成 `PlayerOnlineEvent` 级联加载，再发送 `EnterGameNtf`。
- 当前默认在线模式发布 `RoleEnteredEvent`，直接在 `OnlineTechnicalScene` 创建 `OnlineExpeditionGameplayView`；
  不发送 `EnterMapReq`，不切换 `GameScene/MainPanel`。
- 只有明确回归旧 RPG 保留链时，才继续验证 `EnterMapReq` 与旧 `MainPanel`，且不能把该链当默认产品入口。

## 6. 地图、移动和 AOI

### MAP-01 初始进图

步骤：

1. 完成 `ROLE-04`。

预期：

- 仅在明确执行旧 RPG 回归时进入新手村 `MapCfgId=1, Line=1`；默认在线入口不执行本用例。
- 出生点为 `(100,100)`。
- 场景生成地面、玩家、相机和主界面。
- 收到 `EnterMapNtf` 后，客户端用服务端坐标初始化场景。

### MAP-02 移动同步

步骤：

1. 使用 WASD、方向键或左下角虚拟摇杆移动。
2. 观察小地图坐标。

预期：

- 玩家移动方向和模型朝向一致。
- 坐标变化时客户端发送 `MapMoveReq`。
- `MapMoveAck` 成功时坐标继续更新。
- 若服务端返回错误，客户端发布位置纠正事件。

### MAP-03 地图边界

步骤：

1. 持续向地图边界移动。

预期：

- 客户端会把世界坐标限制在 `1` 到 `地图宽高-1`。
- 不应穿出地图边界。

### MAP-04 地图传送

步骤：

1. 在主界面点击小地图下方“传送”。
2. 在 `ChangeMapPanel` 选择非当前地图并点击“传送”。

预期：

- 面板列出配置表中的三张地图。
- 当前地图显示“当前地图”。
- 传送按钮触发 `ChangeMapReq`。
- 服务端返回 `ChangeMapAck`，并发送 `EnterMapNtf` 和当前视野快照。
- 客户端重建地图场景。

### MAP-05 AOI 双客户端

前置条件：两个不同账号、不同角色进入同一地图。

步骤：

1. 两名玩家靠近。
2. 观察彼此模型是否出现。
3. 其中一名玩家远离。

预期：

- 靠近时收到 `MapObjectsNtf` 增量对象，显示其他玩家。
- 移动时收到 `MapObjectMoveNtf`。
- 远离时收到 `MapObjectsNtf.RemoveObjectIds`，移除其他玩家显示。

## 7. 怪物和战斗

### FIGHT-01 选中目标

步骤：

1. 在新手村靠近怪物。
2. 鼠标点击怪物模型。

预期：

- 客户端设置 `GameData.SelectedTargetId`。
- 主界面目标栏显示目标。
- Unity Console 输出选中怪物日志。

### FIGHT-02 普通攻击

前置条件：已选中怪物，且距离在技能范围内。

步骤：

1. 点击右下角“普攻”按钮，或按键盘 `1`。

预期：

- 客户端发送 `UseSkillReq(SkillId=1, TargetId=目标)`。
- 服务端校验攻击者、技能、目标、距离和 CD。
- 成功后攻击者收到 `UseSkillAck`。
- 目标 HP 降低，视野内对象收到技能效果或 HP 变化通知。

### FIGHT-03 技能异常

| 步骤 | 预期错误 |
|------|----------|

## 8. 背包

### BAG-01 打开和查询背包

步骤：

1. 进入游戏。
2. 点击主界面左侧“背包”。

预期：

- 客户端发送 `QueryBagReq`。
- 新角色首次上线时服务端创建 `RoleBagComponent`，容量为 `100`。
- `QueryBagAck.Items` 为 `List<BagItemInfo>` 完整快照，每个 `BagItemInfo.Uid` 为正数且在列表内唯一。
- 背包面板按 ConfigId、Uid 升序显示动态滚动条目，容量文本例如 `0 / 100`。
- 预置超过 64 个栈时，全部条目可通过滚动访问；预置 105 栈时显示 `105 / 100`，不裁切。

### BAG-02 堆叠、展示返回与变化通知

前置条件：已完成可丢弃 Demo 背包数据重建，并具备任务奖励、怪物掉落或测试数据入口。

步骤：

1. 添加同 ConfigId、Bind、ExpireTime 的多批物品，构造已有多个未满栈。
2. 分别添加 Bind 不同、ExpireTime 不同和相同过去时间值的物品。
3. 添加 MaxStack=1 的木剑或其他装备。
4. 记录 AddItems 返回、`BagItemChangedNtf` 和再次查询的快照。

预期：

- 同一堆叠身份按 Uid 升序填满已有栈，再严格按 ItemConfig.MaxStack 新建 Uid。
- Bind 或 ExpireTime 不同不合并；相同的过去时间值仍按普通元数据合并。
- MaxStack=1 的每件装备拥有独立 Uid。
- AddItems 返回按堆叠身份聚合的本次获得量；通知只发送一次，Items 为变化栈最终绝对 Count。
- 同一通知中一个 Uid 不同时出现在 Items 和 RemovedUids。

### BAG-03 容量与业务准入

分别准备 99、100、101 个实例栈，并确保奖励会新增多个栈。

预期：

- 99/100、100/100 时 `IsFull=false`；101/100 时 `IsFull=true`。
- 100 栈时任务或单封邮件取得准入后，完整批次成功，结束后可以远超 100。
- 101 栈时任务保持未提交，当前邮件保持未领取。
- 同一邮件请求中，第一封使背包超限后，下一封停止领取；第一封已领取状态和附件保留。
- 怪物掉落和通用 GrantItem 在 101 栈以上仍完整添加。
- 整栈扣除使栈数降回 100 后，IsFull 恢复为 false。

### BAG-04 使用请求（效果功能未完成）

前置条件：背包中至少有一个 Uid 栈。

步骤：点击对应条目并在固定 `x1` 确认框中确认使用。

预期：

- 客户端发送只含 `Uid` 的 `BagUseItemReq`，不发送显示序号或 Count。
- 服务端稳定返回 `BagUseItemAck.Error = 道具使用功能未完成`。
- 背包 Count、角色属性和通知数量都不变化。
- 真正效果与扣除测试等待 `GAME1-BAG-01`，不能把当前稳定错误当作效果功能通过。

### BAG-05 客户端角色与断线生命周期

步骤：

1. 角色 A 进入并加载背包，随后切换到角色 B；人为延迟角色 A 的查询响应。
2. 在线时断开网络，重连成功后重新进入角色。
3. 分别测试被踢、主动断开和重连永久失败。

预期：

- 角色 A 的迟到快照不能覆盖角色 B。
- 临时断线期间可以显示只读快照，但点击使用会被客户端阻止。
- 重连重新进角后再次全量查询并替换快照。
- 被踢、主动断开和永久重连失败后背包缓存清空。
- Tidy、Swap、Index 和对应 UI/协议入口均不存在。

前置条件：已接取任务 1。

步骤：

1. 击杀 `CfgId=101` 的野猪。
2. 重复直到任务目标完成。

预期：

- 怪物死亡发布 `MonsterKilledEvent`。
- 任务目标 `击杀怪物 101` 进度递增。
- 内存进度变化后立即推送任务变化并标脏；断线批次保存后重新登录，`CurrentCount` 保持一致。
- 达成目标后任务状态变为 `可提交`。
- 客户端收到 `TaskChangedNtf` 并刷新任务面板。

### TASK-05 提交和放弃

| 场景 | 步骤 | 预期 |
|------|------|------|
| 提交未完成任务 | 选中进行中任务，点击提交 | 服务端返回 `任务未完成` |
| 放弃进行中任务 | 选中进行中任务，点击放弃并确认 | 任务从列表移除，Toast：`已放弃任务` |
| 放弃已完成任务 | 完成任务后点击放弃 | 服务端返回 `任务已完成` |
| 提交已完成任务 | 完成任务后点击提交 | 任务进入已领奖状态，客户端列表移除，奖励物品进入背包 |
| 重复提交任务 | 领奖后再次发送同一提交请求 | 返回 `任务已提交`，背包奖励不重复增加 |
| 领奖后重新登录 | 完成提交后断线并重新登录 | 任务状态为 2，奖励总数与提交完成后一致 |

野猪 101 可能随机掉落 `1001`，自动化判断任务奖励时应断言提交前后数量增加 1，不能断言背包内 `1001` 总数恰好为 1。任务与背包随同一份 `player_entity` 快照保存，并通过重登验证恢复。

当前已接入事件驱动的目标类型：击杀怪物、收集物品、达到等级。对话 NPC、进入场景、使用物品、击杀玩家、通关副本目标类型已有定义但未接入驱动。

## 14. 当前限制和测试注意事项

- Robot 当前覆盖登录、任务持久化、远征完整权威闭环和 Arena 幂等/回放；完整背包容量/扣除、邮件、聊天和
  更广的会话竞争仍需独立场景。旧地图 AOI 不再作为默认产品验证。
- 邮件正向流程没有内置触发入口，需要预置邮件或补测试工具。
- 聊天 UI 当前没有私聊目标输入框，正向私聊只能通过协议测试。
- 旧 `role_*_component` 集合不再读取；没有 `player_entity` 的角色按新玩家创建数据，旧进度不会参与当前验证。
- 背包动态 UI、超过 64 栈滚动和角色生命周期尚未经过当前版本 Unity Editor/PlayMode 验证。
- 道具使用效果尚未完成：请求已固定为按 Uid 使用一件，但效果配置关联、实际扣除和 2005 语义需在独立功能任务中补齐。
- 任务配置中的前置任务、最低等级、经验和金币奖励字段当前没有完整接入提交发奖流程；提交主要发放 `RewardItems`。
- 怪物 AI 已知局限包括单目标仇恨、随机巡逻、攻击后回 Idle、无脱战回血。
- 地图移动当前只做边界限制，没有碰撞和寻路。
- 密码当前明文存储，仅适合内网测试环境。
