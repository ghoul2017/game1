# Codex 规则入口归档

本文记录项目规则入口从 `.claude/`、`codex/` 多入口切换为 `AGENTS.md` 单入口后的处理结果。

## 当前入口

| 内容 | 位置 | 用途 |
|---|---|---|
| 唯一活跃规则入口 | `AGENTS.md` | 安全边界、项目事实、工程约束、验证要求、知识维护方式 |
| 行式知识库 | `docs/line-kb/` | 面向 `rg` 检索的辅助导航层，一行一条项目知识 |
| 需求与计划 | `docs/1.需求.md`、`docs/2.PLAN/`、`docs/3.TODO.md` | 需求拆解和执行依据 |
| 发现事项与遗留风险 | `docs/4.发现需求.md`、`docs/7.遗留问题.md` | 自行发现的问题、遗留风险和后续条件 |
| 模块资料 | `docs/6.模块文档/`、`docs/Robot使用手册.md` | 按需查阅的模块事实和操作说明 |

## 清理结果

- `.claude/` 已清理，不再保存项目规则、命令、agent 配置或项目记忆。
- `codex/` 已清理，不再保存拆分规则文件。
- 旧规则、旧记忆中必须立即遵守的内容已压缩吸收到 `AGENTS.md`；适合检索导航的项目知识已整理到 `docs/line-kb/`。
- Claude 专用流水线、状态栏、子 Agent 配置、过期路径和与当前安全规则冲突的自动回退流程不再作为项目规则保留。

## 维护方式

1. 只有稳定、长期、必须立即遵守的规则，才写入 `AGENTS.md`。
2. 业务决策、调研结论、模块细节和复发问题写入 `docs/` 对应文档。
3. 需要长期检索的路径、入口、跨模块关系和易错点写入 `docs/line-kb/`。
4. 不新增 `codex/rules/`、`.claude/rules/` 或 memory 作为规则来源。
5. 规则如果不能改变实际行为、只是重复已有原则，应删除或合并。
6. 规则如果含糊到会导致不同执行路径，必须改写成触发条件、执行动作和验证标准。

## 冲突处理

- 规则冲突时以 `AGENTS.md` 为准。
- 文档、代码或配置与 `AGENTS.md` 中项目事实冲突时，先读取实际文件确认，再更新规则或文档。
- 从 `docs/1.需求.md` 新拆需求时等待审批；用户在当前对话里直接要求实现时，进入实现阶段后自主推进。
- 不自动 `git push`，不自动回退用户改动，不执行高风险清理，除非用户明确要求。
