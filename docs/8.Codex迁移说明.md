# Codex 规则说明

本文记录项目切换到 Codex 后的规则入口、维护方式和历史资料处理原则。

## 当前入口

| 内容 | 位置 | 用途 |
|---|---|---|
| Codex 主入口 | `AGENTS.md` | 项目总规则、启动读取顺序、权限偏好 |
| 长期规则 | `codex/rules/` | 行为、工作流、代码规范、踩坑、Robot 规范 |
| 需求与计划 | `docs/1.需求.md`、`docs/2.PLAN/`、`docs/3.TODO.md` | 需求拆解和执行依据 |
| 发现事项 | `docs/4.发现需求.md`、`docs/7.遗留问题.md` | 自行发现的问题和遗留风险 |
| Codex 记忆 | `codex/memory/` | 可选项目记忆，不能替代必须执行的规则 |

## 规则维护

1. `AGENTS.md` 保持短入口，只放项目总规则、启动读取顺序和高优先级偏好。
2. `codex/rules/` 保存可复用长期规则：
   - `behavior.md`：行为准则和持久化位置
   - `workflow.md`：需求拆解、执行、验证和 Git 流程
   - `code-conventions.md`：C# 代码规范
   - `pitfalls.md`：踩坑记录和非直觉规则
   - `robot-ai-manual.md`：Robot 项目开发规则
3. 业务决策、调研结论和长期待办写入 `docs/`。
4. 不把必须执行的规则只写进 memory；memory 只记录按需查阅的背景。

## 历史资料处理

- 历史工具目录只作为旧资料，不再作为 Codex 新对话的规则来源。
- 新增或修改规则时，只更新 `AGENTS.md`、`codex/rules/` 或 `docs/`。
- 如历史资料中还有有价值内容，迁入当前入口后再引用当前路径。

## 冲突处理

1. **规则入口**
   - Codex：`AGENTS.md` + `codex/rules/`。
   - 冲突时以 `AGENTS.md` 为准。

2. **需求审批**
   - 从 `docs/1.需求.md` 新拆需求时等待审批。
   - 用户在当前对话里直接要求实现时，进入实现阶段后自动执行。

3. **验证方式**
   - 默认本地复查 + 编译验证。
   - 不依赖历史外部 Agent 名称作为项目流程。

4. **回退机制**
   - 不自动丢弃工作区改动。
   - `git reset`、`git checkout` 回退、递归删除等高风险操作需要用户明确要求。

5. **Git**
   - 项目偏好是实现后自动 commit。
   - 不自动 `git push`。

6. **权限**
   - 用户希望 Codex 在项目内高自主执行。
   - 遇到 sandbox 或文件权限阻塞时，直接发起提升权限请求。
