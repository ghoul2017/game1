# Codex 迁移说明

本文记录从 Rider + Claude Code 迁移到 Codex 后的规则对应关系、冲突处理和维护方式。`.claude/` 保留，不删除、不移动。

| Claude 文件 | Codex 中的处理 |
|---|---|
| `.claude/CLAUDE.md` | 历史入口，内容大部分已同步到 `AGENTS.md`；冲突时以 `AGENTS.md` 为准 |
| `.claude/rules/behavior.md` | 有效，作为长期行为规则读取 |
| `.claude/rules/workflow.md` | 部分有效，涉及审批、回退、子 Agent 的规则按下方冲突处理 |

| `.claude/memory/MEMORY.md` | 仅作历史索引；重要规则不依赖 memory 自动加载 |
| `.claude/agents/*.md` | Claude Code 专用 Agent 定义，Codex 不直接执行 |

## 冲突处理

1. **规则入口**
   - Claude Code：`CLAUDE.md` / `.claude/`。
   - Codex：`AGENTS.md`。
   - 冲突时以 `AGENTS.md` 为准，必要时再查 `.claude/rules/`。

2. **需求审批**
   - `.claude/rules/workflow.md` 要求“计划生成后必须等用户确认”。
   - Codex 当前采用：从 `docs/1.需求.md` 新拆需求时等待审批；用户在对话里直接要求实现时，进入实现阶段后自动执行。

3. **验证 Agent**
   - Claude 规则要求每次改动后并行 `verify-feature` + `verify-quality`。
   - Codex 当前采用：默认本地复查 + 编译验证；只有用户明确要求子 Agent/并行 Agent 时才启动子 Agent。

4. **回退机制**
   - Claude 规则写有 `git checkout -- <files>` 回退。
   - Codex 当前采用：不自动丢弃工作区改动；需要用户明确要求才能执行破坏性回退。

5. **记忆位置**
   - Claude 历史规则使用 `.claude/memory/`。
   - Codex 当前项目重要信息优先写入 `docs/` 和 `.claude/rules/`；`.Codex/memory/` 仅用于未来新增 Codex 专用项目记忆。

6. **Git**
   - 项目偏好是实现后自动 commit。
   - 当前环境 `.git/index.lock` 写入权限受限，commit 可能失败；代码改动和编译验证仍可完成。

## 建议的维护方案

- `AGENTS.md` 保持短入口：项目总规则、启动读取顺序、冲突处理原则。
- `.claude/rules/` 保留为长期规则库：行为、工作流、代码规范、踩坑、Robot 规范。
- `docs/` 保留为需求、计划、TODO、模块文档、遗留问题和迁移说明。
- 不把必须执行的规则只写进 memory；memory 只记录按需查阅的背景知识。
- 规则变更后优先更新 `AGENTS.md` 的触发条件，确保 Codex 能知道“什么时候读哪些文件”。
