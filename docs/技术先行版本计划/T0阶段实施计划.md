## 2. T0 的唯一业务行为

实现最小固定 Tick 移动：

`初始 ExpeditionState + MoveCommand -> ExpeditionSession.Step() -> Tick 增加且队伍根位置变化`

行为约束：

1. `MoveCommand` 只包含 X/Y 方向，不包含绝对位置、时间、速度和网络字段。
2. 输入长度大于 1 时由核心归一化或裁剪；无效浮点值必须拒绝。
3. 每次 `Step` 固定增加一个 Tick；移动距离由构造时传入的 `MovePerTick` 决定。
4. 零方向仍推进 Tick，但位置不变。
5. 同一构建中，相同初始状态和命令流连续运行得到相同最终状态。
6. 该行为是后续队伍根、自动目标和房间规则的真实起点，不创建占位 Manager、空事件总线或通用 ECS。

T0 使用 `float` 位置，不实现固定点。正式结果由服务端权威计算，T0 不承担跨平台逐位重演协议。

## 3. 工程边界

### 3.1 源码与编译方式

唯一规则源码放在：

```text
client/Assets/Scripts/GameplayCore/
```

编译消费者：

```text
Unity 2022.3.62f3c1
  -> GameplayCore.asmdef 编译 Assets 中的真实源码

gameplay-core/GameplayCore.csproj (netstandard2.1)
  -> 链接同一目录源码，不复制文件

tests/GameplayCore.Tests (net8.0)
  -> 引用 GameplayCore.csproj
```

`GameplayCore.csproj` 不允许任何 `ProjectReference` 或 `PackageReference`。测试包只存在于测试工程。

### 3.2 禁止依赖

`GameplayCore` 源码不得使用：

- `UnityEngine` 和 MonoBehaviour；
- `Shared`、Server、MongoDB、Protobuf；
- `System.Net`、`System.IO`；
- `DateTime`、`DateTimeOffset`、`Stopwatch`、Unity `Time`；
- `System.Random`、Unity 随机；
- `Task.Run`、线程、Timer、并发容器；
- 全局可变单例、Service Locator 和反射注册。

T0 只依赖 `System` 中实现值对象与数学所需的基础 API。

## 5. 最小公开模型

建议模型保持三个类型，不为“以后可能需要”增加通用头和版本对象。

### `MoveCommand`

- `float DirectionX`
- `float DirectionY`
- 构造时拒绝 NaN 和 Infinity。
- 输入长度为 0 表示停止；大于 1 的归一化策略由核心统一执行。

### `ExpeditionState`

- `long Tick`
- `float SquadX`
- `float SquadY`
- 只读公开状态；外部不能直接写位置或 Tick。

### `ExpeditionSession`

- 构造参数：初始状态、正数 `movePerTick`。
- `State`：当前只读状态。
- `Step(MoveCommand command)`：唯一写入入口。
- 单线程使用，不在类型内部加锁。

不在 T0 增加 `SimulationVersion`、`ConfigVersion`、`GeneratorVersion`、固定点、稳定实体 ID、快照头、事件头和结果头。哪个真实行为首先需要它，在哪个阶段连同测试一起加入。

## 6. 测试清单

最低行为测试：

1. 零输入只增加 Tick。
2. 单位 X 方向按 `movePerTick` 移动一次。
3. 斜向和超长方向不会比单位方向移动更远。
4. 多 Tick 命令流得到预期 Tick 和位置。
5. 两个独立 Session 使用相同初态和命令流得到相同状态。
6. NaN、Infinity、负 Tick、非正 `movePerTick` 被拒绝。
7. 外部不能修改 `ExpeditionState`。

测试比较浮点时使用明确误差容限；不得把当前运行时偶然逐位一致写成跨平台保证。

架构门禁由脚本负责，不再复制一套读取源码字符串的 xUnit “测试”。

## 9. 验证顺序

在真实项目根运行：

```bash
dotnet restore tests/GameplayCore.Tests/GameplayCore.Tests.csproj
dotnet build gameplay-core/GameplayCore.csproj
dotnet test tests/GameplayCore.Tests/GameplayCore.Tests.csproj
bash scripts/check-gameplay-core-boundary

```

`git diff --check` 不读取未跟踪文件；T0 在未获暂存授权时，还必须用 Git Bash 检查全部未跟踪文件：

```bash
while IFS= read -r -d '' path; do
    issues="$(git diff --no-index --check -- /dev/null "$path" || true)"
    if [ -n "$issues" ]; then
        printf '%s\n' "$issues"
        exit 1
    fi
done < <(git ls-files --others --exclude-standard -z)
```

获得暂存授权后，提交前再运行 `git diff --cached --check`，它不能被上述未跟踪文件检查代替。

上述 `bash` 命令应在 Git Bash 中执行。当前 Windows PowerShell 的 `bash` 会命中未配置的 WSL；在 PowerShell 中应显式调用 Git for Windows：

```powershell
$gitRoot = Split-Path (Split-Path (Get-Command git).Source -Parent) -Parent
$gitBash = Join-Path $gitRoot 'bin\bash.exe'
& $gitBash scripts/check-gameplay-core-boundary
& $gitBash scripts/check-all
```

Unity Editor 生成的 `.meta` 会为空 YAML 值保留冒号后的空格；仓库通过 `.gitattributes` 的
`*.meta whitespace=-blank-at-eol` 声明该格式例外，禁止为追求 `git diff --check` 全绿而手工改写 `.meta`。
