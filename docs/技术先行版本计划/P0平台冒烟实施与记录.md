P0 只回答一个问题：当前 `game1` 能否以很小的改动在目标小游戏环境完成“启动、序列化、异步读取、双向网络”四条基础链路。

P0 不实现正式登录、业务 WebSocket 网关、资源热更、玩法、商业化或性能优化。

## 2. 当前已核实基线

实施前必须重新核对；以下事实只代表文档创建时的已跟踪基线和未重叠文件：

| 项目 | 当前事实 | P0 风险 |
| --- | --- | --- |
| Unity | `2022.3.62f3c1` | 必须用精确版本及其 WebGL Build Support |
| 微信 SDK | `client/Packages/manifest.json` 尚未安装转换 SDK | 安装会修改 manifest/lock，必须固定完整 revision |
| 网络 | HEAD 中 `TcpSession` 使用 `System.Net.Sockets` | WebGL 不支持，P0 另建隔离 WebSocket 冒烟，不修改该并行热点文件 |
| 序列化 | Shared 使用 `protobuf-net 3.2.45` | 需要验证 IL2CPP/AOT 和裁剪后的直接序列化与注册 |
| 消息注册 | `MessageRegistry` 扫描已加载程序集和 Attribute | 反射类型在 AOT/裁剪后可能缺失，必须真机构建验证 |
| 配置读取 | `GameEntry -> ConfigManager -> File.ReadAllLines` 同步读取 `StreamingAssets/Tables` | WebGL 需要异步读取；P0 只验证独立样例，不在此阶段改造正式配置系统 |

不得读取当前脏 `TcpSession` 内容形成方案结论；网络事实以 HEAD 基线和 Unity 官方平台限制为准。

| 状态 | 定义 | 后续影响 |
| --- | --- | --- |
| `通过` | 开发者工具和至少一台目标设备完成全部四条链路 | 允许按上位方案进入 T0/T1 |
| `条件通过` | 开发者工具全部通过，但真机、AppID 或 WSS 域名受外部条件阻塞 | 可继续纯核心验证；不得进入 T3 正式联机 |
| `失败` | 工具链、AOT、异步读取或 WebSocket 任一链路有可复现技术失败 | 先解决最短失败链路，不扩玩法 |
| `豁免` | 负责人书面改变首发平台或接受未验证风险 | 记录决定、范围和责任人，不写成技术通过 |

“能导出”不等于通过；“Editor/浏览器能运行”也不能替代微信开发者工具和真机证据。

## 4. 实施边界

### 4.1 允许的计划范围

取得 P0 代码授权后，预期只改：

- `client/Packages/manifest.json` 和 `client/Packages/packages-lock.json`：安装固定 revision 的官方 SDK；
- `client/Assets/P0PlatformSmoke/`：独立 Scene、Runner 及由 Editor 生成的 `.meta`；
- `client/Assets/StreamingAssets/P0PlatformSmoke/p0-smoke.csv`：仅供异步读取验证的固定样例；
- 本文件：填写环境、结果和证据路径。

构建输出必须写到 Git 根之外的新建任务专用临时目录。不得把导出目录、微信项目、缓存或凭据放进仓库。

SDK 导入或导出若产生其他跟踪文件变化，先列出实际文件和原因并停止；确认属于必要平台配置后再重新授权范围。

### 4.2 明确不修改

- 当前 `TcpSession`、`NetworkComponent`、正式协议处理和 Server；
- `GameEntry`、`ConfigManager`、`SimpleCsvReader` 和正式 CSV；
- T0 `GameplayCore`、旧 RPG、场景入口和业务 UI；
- 微信公众平台/小游戏后台的生产 AppID、域名、密钥和发布配置；
- 正式登录、支付、广告、排行榜、云存储和热更新。

P0 发现的问题进入结果表和后续改造清单，不在同一阶段顺手修完整系统。

## 6. 冒烟载荷

独立 `P0PlatformSmoke` 场景只包含一个 Runner 和文本日志，按固定顺序输出：

```text
P0_BOOT
P0_PROTO_OK
P0_CONFIG_OK
P0_WS_OK
P0_READY
```

验证载荷固定为：

- Protobuf：`HeartbeatReq { ClientTime = 123456789 }`；
- 消息名：`Misc.HeartbeatReq`；
- PacketCodec：编码后通过 WebSocket 二进制 echo 原样返回并再次解码；
- 配置：独立 `p0-smoke.csv`，异步读取后核对固定 SHA-256 或固定字段；
- 网络：连续 20 次小包 echo，记录成功数、RTT 中位数和 P95。

禁止使用生产账号、生产服务器和生产数据。公共第三方 echo 只能用于临时排障，不能作为最终通过证据。

## 7. 执行步骤

### P0.0 基线（0.5 小时）

1. 读取项目档案，确认 Git 根、origin、分支和 HEAD。
2. 记录 `git status --short --untracked-files=all`、cached diff 和进行中的 Git 操作。
3. 检查第 4.1 节目标不存在归属不明的重叠改动。
4. 确认精确 Unity、WebGL 模块、Git 客户端、开发者工具、AppID 和 endpoint 可用性。

门禁：范围与外部条件已记录；不能获取的条件已有明确降级状态。

### P0.1 官方 SDK 与空场景启动（1–2 小时）

1. 解析官方 SDK 当前拟用 revision，使用完整 commit SHA 固定 Git 依赖，禁止直接依赖移动的 `main`。
2. 用 Unity Package Manager 安装；记录 manifest、lock 和依赖解析 diff。
3. 创建隔离场景并输出 `P0_BOOT`；不加载正式 `GameEntry`。
4. 导出到仓库外目录，在微信开发者工具冷启动三次，记录成功率、错误和首次 `P0_BOOT` 时间。

门禁：三次均可启动，Console 无阻断 Error；否则状态为`失败`。

### P0.2 Protobuf、消息注册与裁剪（0.75–1 小时）

1. 构造固定 `HeartbeatReq`，完成序列化、反序列化和字段相等检查。
2. 调用现有消息注册，确认类型到 `Misc.HeartbeatReq` 及反向解析均成功。
3. 经 `PacketCodec` 编码、解码并核对消息名与 payload。
4. 只以导出后的开发者工具/真机运行结果判定 AOT；Editor 结果只作排障线索。

门禁：输出一次 `P0_PROTO_OK`；缺类型、反射异常、裁剪异常或字段不一致均失败。

### P0.3 异步配置读取（0.5–1 小时）

1. 从 `StreamingAssets/P0PlatformSmoke/p0-smoke.csv` 构造平台 URL 并读取固定样例。
2. 使用 `UnityWebRequest` 或官方 SDK 推荐的异步文件 API 读取；等待期间必须把控制权交还运行时。
3. 核对内容哈希/字段并输出 `P0_CONFIG_OK`，记录读取耗时。
4. 不调用同步 `File.ReadAllLines`，也不修改正式配置管理器。

门禁：开发者工具与真机读取结果一致；阻塞轮询、空内容或路径特判均不通过。

### P0.4 WebSocket 二进制 echo（0.75–1.5 小时）

1. 使用官方 SDK 提供或明确支持的 WebSocket 路径，不把 `.NET System.Net` socket 带入 WebGL。
2. 连接授权的测试 endpoint，设置连接、单次请求和总测试超时。
3. 连续发送 20 个 PacketCodec 二进制包；校验返回字节、消息名和 Protobuf 字段。
4. 记录成功数、RTT、断开原因和 Console 网络错误，完成后主动关闭连接。

门禁：20/20 成功且无数据损坏时输出 `P0_WS_OK`；仅文本 echo 或本机浏览器成功不能作为真机网络通过。

### P0.5 真机、指标与收口（1–2 小时）

1. 在至少一台目标设备执行完整流程，记录从启动到 `P0_READY` 的时间。
2. 记录开发者工具报告的初始包/分包数据、构建目录字节数、峰值内存和 60 秒稳定运行错误。
3. 再次检查 Git 状态，确认只有第 4.1 节计划文件及已确认 SDK 必需变化。
4. 填写第 8 节，给出唯一最终状态和 T0/T1/T3 准入结论。

门禁：证据完整且能区分开发者工具与真机；未测数据不得填 0 或“正常”。

## 9. 停止条件

出现以下任一情况时停止并保留证据：

1. 目标文件或 Package manifest/lock 已有归属不明的并行改动。
2. SDK 不支持精确 Unity 版本，或依赖解析要求升级 Unity/替换核心包。
3. SDK/Editor 产生第 4.1 节外的跟踪变化，且归属或必要性无法确认。
4. 需要生产 AppID、密钥、域名配置、生产服务或外部写操作才能继续。
5. 只能修改当前并行热点 `TcpSession`、正式配置管理器或 Server 才能完成隔离冒烟。
6. 导出、AOT、配置或 WebSocket 同一失败在清理缓存后可稳定复现。
7. 构建输出进入 Git 根或包含凭据、token、用户数据。

失败不是扩大架构的授权。报告失败链路、复现环境和最小下一步后停止。
