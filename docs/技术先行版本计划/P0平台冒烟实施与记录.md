## 6. 冒烟载荷

独立 `P0PlatformSmoke` 场景只包含一个 Runner 和文本日志，按固定顺序输出：

```text
P0_BOOT
P0_SDK_OK
P0_PROTO_OK
P0_CONFIG_OK
P0_TCP_OK
P0_READY
P0_STABLE_60S
```

验证载荷固定为：

- Protobuf：`HeartbeatReq { ClientTime = 123456789 }`；
- 消息名：`Misc.HeartbeatReq`；
- PacketCodec：编码后通过平台 TCP 二进制 echo 原样返回并再次解码；
- 配置：独立 `Resources/p0-smoke.csv`，随包异步读取后核对固定字段；
- 网络：连续 20 次小包 echo，记录成功数、RTT 中位数和 P95。

禁止使用生产账号、生产服务器和生产数据。公共第三方 echo 只能用于临时排障，不能作为最终通过证据。

## 7. 执行步骤

### P0.0 基线（0.5 小时）

1. 读取项目档案，确认 Git 根、origin、分支和 HEAD。

4. 确认精确 Unity、WebGL 模块、Git 客户端、开发者工具、AppID 和 endpoint 可用性。

门禁：范围与外部条件已记录；不能获取的条件已有明确降级状态。

### P0.1 官方 SDK 与空场景启动（1–2 小时）

1. 解析官方 SDK 当前拟用 revision，使用完整 commit SHA 固定 Git 依赖，禁止直接依赖移动的 `main`。
2. 用 Unity Package Manager 安装；记录 manifest、lock 和依赖解析 diff。
3. 创建隔离场景并输出 `P0_BOOT`；不加载正式 `GameEntry`。
4. 导出到仓库外目录，在微信开发者工具冷启动三次，记录成功率、错误和首次 `P0_BOOT` 时间。

门禁：三次均可启动，Console 无阻断 Error；否则状态为`失败`。

### P0.2 Protobuf、消息注册与裁剪（0.75–1 小时）

1. 构造固定 `HeartbeatReq`，完成序列化、反序列化和字段相等检查。
2. 调用现有消息注册，确认类型到 `Misc.HeartbeatReq` 及反向解析均成功。
3. 经 `PacketCodec` 编码、解码并核对消息名与 payload。
4. 只以导出后的开发者工具/真机运行结果判定 AOT；Editor 结果只作排障线索。

门禁：输出一次 `P0_PROTO_OK`；缺类型、反射异常、裁剪异常或字段不一致均失败。

### P0.3 异步配置读取（0.5–1 小时）

1. 首轮固定样例来自 `StreamingAssets/P0PlatformSmoke/p0-smoke.csv` 并通过仓库外平台 URL 排障；局域网续测将唯一固定样例移到 `P0PlatformSmoke/Resources/p0-smoke.csv` 随包发布。
2. 局域网续测使用 `Resources.LoadAsync<TextAsset>`；等待期间把控制权交还运行时，不为随包样例部署远程 HTTPS。该证据不替代正式 `StreamingAssets/Tables` 的异步迁移。
3. 核对内容哈希/字段并输出 `P0_CONFIG_OK`，记录读取耗时。
4. 不调用同步 `File.ReadAllLines`，也不修改正式配置管理器。

门禁：开发者工具与真机读取结果一致；阻塞轮询、空内容或路径特判均不通过。

### P0.4 平台二进制 echo（0.75–1.5 小时）

1. 不直接把 `.NET System.Net` socket 带入 WebGL；首轮使用 `wx.connectSocket` 排障，局域网续测使用当前 SDK 的 `WX.CreateTCPSocket()`。

4. 记录成功数、RTT、断开原因和 Console 网络错误，完成后主动关闭连接。

门禁：20/20 成功且无数据损坏；首轮 WebSocket 证据输出 `P0_WS_OK`，平台 TCP 续测输出 `P0_TCP_OK`。仅文本 echo、裸公网 IP 或本机浏览器成功不能作为真机网络通过。

### 8.1 2026-08-01 正式链路跟进

- 网络：`IByteTransport` 建立平台无关字节传输边界；原生使用 `SocketByteTransport`，微信 WebGL 使用
  `WeChatClientTransport` 和 `WX.CreateTCPSocket()`。`TcpSession` 选择 Reliable/Latest 语义，两种 Transport
  实现各自持有 1 MiB 有界可靠队列、最新状态槽和发送循环；同时修复断开/释放竞争和陈旧连接代次。
- 配置：`GameEntry` 通过 `UnityWebRequest` 异步取得全部必需 CSV；`SimpleCsvReader` 执行严格 schema/type
  校验，`ConfigManager` 只有在全部表成功后才原子替换快照，失败时阻断启动且保留旧快照。
- 编译证据：正式微信传输条件分支已用当前 SDK 程序集做补充 API 形状编译；这不是 Unity WebGL/IL2CPP 证据。
  当前精确 Unity 安装缺少 WebGL Build Support，实际导出在切换目标前被阻断。
- 验收边界：尚未在开发者工具或真机运行正式登录、RPC、服务端推送、主动/异常断开、重连与完整配置启动链；
  因此 `GAME1-PLATFORM-01/02` 从“未实现任务”收口为“工程已完成、目标设备待验收”。

## 9. 停止条件

出现以下任一情况时停止并保留证据：

1. 目标文件或 Package manifest/lock 已有归属不明的并行改动。
2. SDK 不支持精确 Unity 版本，或依赖解析要求升级 Unity/替换核心包。
3. SDK/Editor 产生第 4.1 节外的跟踪变化，且归属或必要性无法确认。
4. 需要生产 AppID、密钥、生产服务或未经授权的外部写操作才能继续；已授权的 `gridpursuit` AppID 非生产测试操作不属于此项。
5. 只能修改当前并行热点 `TcpSession`、正式配置管理器或 Server 才能完成隔离冒烟。
6. 导出、AOT、配置或平台网络同一失败在清理缓存后可稳定复现。
7. 构建输出进入 Git 根或包含凭据、token、用户数据。

失败不是扩大架构的授权。报告失败链路、复现环境和最小下一步后停止。
