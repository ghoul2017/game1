# 百炼 Like 技术先行完整交付报告

目标读者：人类。

## 1. 结论

本线程已完成《百炼 Like 技术先行落地方案》的 P0–T6 工程链，并把联机入口补到可在单机上真实启动
Server/MongoDB、登录、操作、终局、结算、升级和进入第二局的灰盒测试水平。

当前准确状态是“本机联机技术测试版本可用”，不是商业成品：人工手感、目标设备、WebGL/微信、弱网、
MongoDB 故障、Linux/生产容量和正式 IP 内容仍有独立门禁，均已登记。

用户测试过程中出现的三个直接问题也已解决：服务端可从 Unity 一键启动；登录后默认进入新在线远征，不再显示
旧 RPG 地图；持续移动不再被每个普通权威快照周期性向后拉。

## 2. 整个线程完成了什么

### P0：正式配置与平台传输基础

- `GameEntry` 改为以 `UnityWebRequest` 异步加载全部必需 CSV；严格校验后由 `ConfigManager` 原子切换完整快照，
  缺表或坏表在 Context/UI/网络启动前阻断。
- `TcpSession` 依赖最小 `IByteTransport`；Server、Robot、Editor/原生客户端使用 `SocketByteTransport`，微信条件
  分支使用 `WeChatClientTransport` 适配 `WX.CreateTCPSocket()`。
- 可靠发送队列限制为 1 MiB，普通高频状态使用 `SendLatest` 覆盖尚未发送的旧快照；重连连接代次阻止陈旧
  Session 覆盖新连接。
- 当前没有 WebGL Build Support，因此只保留 SDK API 形状和历史平台冒烟证据，没有把它写成当前 WebGL/IL2CPP
  通过。

### T0–T2：同源规则与本地完整小闭环

- `GameplayCore` 是 Unity、Server 和 .NET 测试共用的唯一物理源码，完成队伍根移动、成员跟随、稳定目标、
  自动战斗/采集、Boss 警告、确定性房间图、路线与门、唯一终态、成功/失败带回、基地升级和第二局隔离。
- T1 `ExpeditionHandfeelScene` 保留短局手感回归；T2 `ExpeditionVerticalSliceScene` 提供 6–10 房间的本地完整闭环。
- Golden Seed、固定 256 Seed 扫描、失败恢复、先扣后加升级和第二局继承均有行为测试。

### T3–T4：服务端权威与永久进度

- Server 以 10 Hz 单写者推进，每 2 Tick 下发一次 5 Hz 完整小快照；客户端只预测队伍根，敌人、伤害、资源、
  房间、结果与收益全部由服务端决定。
- 输入包含量化方向、交互目标和单调序号；每秒最多接受 30 条，500 ms 无有效输入后归零。共享量化函数会保证
  四舍五入后的方向仍在单位圆内。
- 快照携带 Tick、移动速度、边界、Boss 警告半径；永久进度携带升级价格、上限和代表伤害，客户端不再硬编码。
- `ExpeditionEventBatchNtf` 传送战斗、采集、房间与危险表现事件；可靠性边界是当前 TCP 连接，尚无跨重连 ACK。
- 一账号最多一个活动局；断线后同进程保留 5 分钟并以零输入推进。重连令牌在线不可消费，断线后开启窗口，
  首次消费轮换；重放返回同一结果。
- Start RequestId 在活动/保留宿主内幂等：相同请求返回原局，不同请求拒绝；完成局保留期内相同 ID 不能重开。
- 结算先消费结算权，再增加玩家聚合资源；升级先扣资源再加等级。进度、回执和升级交给现有 `PlayerEntity`
  合批保存，不插入绕过聚合的即时 MongoDB 保存。
- 网络包路由和断线业务清理都经 `GameSynchronizationContext` 单写者线程，避免 Socket 回调与 Tick 并发修改 Host。

### T5：异步 Arena

- 服务端读取进攻方快照和固定防守副本，分配 BattleId/Seed，一次性运行到唯一终态。
- 同角色、同 RequestId 只运行一次；重复请求返回相同摘要。回放支持 1 倍、4 倍和跳过，播放不重跑规则。
- 完整回放和幂等摘要有容量与 TTL 上限；赛季、排行、奖励、匹配池和长期持久化明确不在技术先行范围。

### T6：双产品隔离

- `ProductContent` 保存 `labyrinth` 与 `cosmic_legion_placeholder` 两个中性 Profile 的主题、阵容、敌人、资源和规则
  参数，不把品牌词写入共享核心。
- `ProductExpeditionFactory` 是唯一组合入口；本地 Host 与 Server 都由它构建 Setup/Campaign/Run，不再有两套默认
  产品参数。
- 第二 Profile 的 180 秒规则由 10 Hz Tick 精确推进到第 1800 Tick，触发产品中立的唯一失败终态；新局重置。

### 本轮追加：完整在线表现与安全测试入口

- 新增 `OnlineExpeditionGameplayView/WorldView/InputView`，表现队伍、敌人、资源、房门、路线、Boss 危险圈、
  终局、基地、升级和第二局；支持 WASD、方向键和触摸摇杆。
- `OnlineTechnicalScene` 改为默认入口。角色就绪后直接挂载在线 Gameplay，不发送旧 `EnterMapReq`、不切换
  `GameScene`；重连失败、被踢、断线和网络错误可回登录页。
- Arena 收进可折叠诊断抽屉，不遮挡远征主玩法。
- 新增 Unity Editor 本地服务端窗口和一键构建/启动/Play/停止链，详见第 7 节。
- 普通同房间快照不再在回调内以 `deltaTime=0` 强制渲染；预测校正仅有限豁免权威快照已证明的同向采样滞后，
  同 Tick 重复样本直接忽略。变化方向输入最高 20 Hz，首次移动、停步和交互变化保持立即发送。
- 使用中枢 `node tools/codex-usage.mjs` 检查资源；当时主窗口剩余 72%，未因此缩减实现或验收范围。

## 3. 为什么采用这些边界

- 权威状态只在 Server：客户端没有提交位置、伤害、掉落或收益的能力，单机测试版与后续联网版不会形成两套经济
  语义。
- 先用完整小快照：当前房间实体和包体很小，容量证据不足以支持提前引入 delta、AOI、回滚或分片复杂度。
- 规则、内容、组合单向依赖：`GameplayCore` 保持产品中立，`ProductContent` 不反向依赖规则，
  `ProductExpedition` 只负责组合真实差异。
- Editor 启动器优于正式 Player 自启：测试方便，同时避免正式客户端携带 .NET SDK、Server、MongoDB 或进程控制
  权限。
- 旧 RPG 先屏蔽再精确删除：登录、Session、封包、配置、玩家聚合与持久化仍被新入口复用，直接按目录删除会
  误伤基础设施。

## 7. Unity 一键本地服务端

菜单：

- `Tools/Online Technical/Local Server Window`
- `Tools/Online Technical/Build, Start Server and Play`
- `Tools/Online Technical/Stop Local Server`

工具读取 `global.json` 要求的 SDK（本机实际使用 `8.0.423`），构建 Server，并固定从仓库 `bin/` 执行
`dotnet Server.dll`。本地模式仅监听 `127.0.0.1:9000`；普通服务端仍使用配置地址。

启动前检查 MongoDB `127.0.0.1:27017` 和 9000。工具不会启动/修改 MongoDB，也不会接管或停止未知 9000
监听者。停止路径通过 Unity PID、Server PID/启动时间、随机 token 和控制文件确认所有权，优先等待最多 20 秒
优雅保存，超时也只终止完全匹配的自有进程。启动就绪目前仍是“自有进程存活 + 任意 9000 监听”；监听归属的
TOCTOU 缺陷记为 `GAME1-TOOL-01`，修复方案为 `GAME1-ENG-12`。状态位于忽略目录
`client/Library/Game1LocalServer`。

Player 和正式客户端不会包含或自动启动服务端。自动 MongoDB、跨平台独立编排器或测试 Player 伴随服务是否需要，
由 `GAME1-ENG-10` 后续评估。

### 移动回退专项修复

根因不是服务端速度或单位错误：服务端 10 Hz 按 `5.5 units/s` 权威推进，5 Hz 快照天然落后当前客户端渲染时刻；
旧客户端却对每个快照无条件向权威位置混合 35%，随后视图又用零帧时长立即渲染，因此形成固定周期的后跳。

修复保持服务端权威：先按原始误差执行 2 单位硬纠正；普通同 Run/Room/Phase 快照只消除相邻新 Tick 权威坐标
已经证明的同向位移，且最多 1.5 单位。权威停步、客户端停步、横向误差、房间/阶段变化和大偏差仍会纠正，避免
把“无回退”做成客户端永久漂移。模拟摇杆连续变化按 50 ms 合并，防止正常输入超过服务端 30 条/秒限制。

专项回归覆盖普通滞后不回拉、服务端停步仍收敛、大偏差硬纠正、滞后豁免有界、停步收敛、快速摇杆合并、同 Tick
去重，以及普通快照不能让可见队伍瞬移。电脑控制已用既有账号 `1231`、角色 `123` 进入真实 Run
`342152663099510784`，确认启动、登录、选角和在线世界链路；该控制接口只能发送离散按键，不能保持按键状态，
因此没有把这次现场操作写成持续移动手感通过，正式证据使用可重复的 .NET 与 PlayMode 测试。

## 9. 现在如何人工测试

1. 确认 MongoDB 能连接 `127.0.0.1:27017`。
2. 用 Unity `2022.3.62f3c1` 打开 `client/`。
3. 点击 `Tools/Online Technical/Build, Start Server and Play`。
4. 登录；新账号会自动注册。创建或选择角色后应直接看到远征世界，不应出现旧 RPG 地图。
5. 持续按住 WASD/方向键或拖住触摸摇杆移动；队伍应连续前进，不应按约 200 ms 快照周期逐步后跳。松手、撞到
   房间边界或切换房间时允许平滑/硬性回到权威状态。
6. 完成终局并结算，回基地升级训练设施，再开始第二局；第二局代表伤害应提高。
7. 展开在线诊断面板可测试 Arena 的开始、回放、1 倍、4 倍和跳过。
8. 用 `Stop Local Server` 停服或退出 Unity；确认日志完成保存且 9000 不再监听。

详细步骤与失败判定见 `docs/test-manual.md` 的“本机在线技术版本”。
