#### 正式平台基础链

- `TcpSession` 改为依赖最小 `IByteTransport`；Server、Robot 和原生客户端使用 `SocketByteTransport`，微信
  WebGL 使用 `WeChatClientTransport` 适配 `WX.CreateTCPSocket()`，继续复用现有 PacketCodec、RPC 和消息路由。
- 可靠发送队列限制为 1 MiB；普通快照以 `SendLatest` 替换尚未发出的旧状态。发送循环统一负责传输/缓冲收尾，
  修复接收循环与释放竞争；`NetClient` 用连接代次阻止陈旧异步连接覆盖新 Session。
- `GameEntry` 使用 `UnityWebRequest` 异步取得全部必需 CSV；`SimpleCsvReader` 严格验证 schema/type，
  `ConfigManager` 只有在全部表成功解析后才原子切换快照，失败在 Context/UI/网络启动前阻断。
- 当前 SDK 程序集下的微信条件分支补充 API 形状编译为 0 Error；独立 .NET 编译产生 16 条 Unity/SDK 程序集
  版本冲突警告，因此只作为 API 形状证据，不能替代 Unity WebGL/IL2CPP。

#### T3/T4 在线远征与会话权威

- 服务端 `ExpeditionRunHost` 以 10 Hz 单写者推进同源规则，每 2 Tick 通过 `SendLatest` 下发 5 Hz 完整快照；
  每秒最多 30 条输入，输入 500 ms 后归零。客户端只预测队伍根并按权威房间/阶段与距离纠正。

  不计时且不可消费，权威断线后开启 5 分钟 Recovery；首次消费轮换，原窗口内旧 token 重放返回同一新 token。
  pending EnterGame 成功才提交 token/清约束；响应丢失、EnterGame 失败和提交前再次断线均已有回归。

  回执冻结结算时设施等级，`ProgressRevision` 和刷新后的 retained checkpoint 防止旧 Run 回灌新结算/升级。
- 登录先验证凭据再踢旧会话；EnterGame 每个数据库 await 后复核当前 User.Session。Player RPC/Ntf 同时核验
  RoleId 与 `PlayerOnline.Session`，陈旧连接不能修改当前玩家。
