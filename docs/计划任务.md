## 使用与收口规则

1. 用户明确选择一个任务 ID 或给出等价的单一目标后，才读取和执行对应任务；其他条目不随之获得授权。
2. 进入任务前读取中枢 `projects/game1/AGENTS.md`、相关 line-kb 和条目列出的事实来源，并重新核对真实项目 Git 现场。
3. 产品语义、协议权威、数据迁移或安全等级未确定时，先给出证据和影响，由用户决定后再实现。
4. 每个任务独立修改和验证；测试会启动服务、进入 PlayMode、创建账号或写入 MongoDB 时，先确认环境和数据授权。
5. 完成后把实际结果写入当月 `docs/工作记录/YYYY-MM.md`，把未执行验证写入 `docs/测试列表.md`，同步更新中枢 line-kb，并从本文件移除该条目。
6. 只有已经存在且对追溯有用的真实提交，才在工作记录中以“关联版本”记录。

### GAME1-PLATFORM-01：正式客户端传输适配微信小游戏

- 状态：T3 前计划任务；不阻断当前纯核心与本地玩法 Demo。
- 原因：正式链路由 `NetworkComponent` 创建 `TcpSession`，客户端 `NetClient` 最终使用 `System.Net.Sockets`；WebGL 不能直接运行该 .NET 实现。官方微信 SDK v0.1.31 已提供 `WX.CreateTCPSocket()`、二进制写入和消息回调，P0 也已建立隔离的局域网 TCP 冒烟入口，并用窄兼容桥补齐该版本回调期望的 Unity UTF-8 运行时函数，但尚未接入正式登录、RPC、推送与断线链路。
- 目标：建立平台无关的客户端传输边界；Server 和 Robot 保留现有 TCP，微信小游戏可用平台 `TCPSocket` 适配，浏览器和其他小游戏平台由各自适配器接入，同时复用现有封包、RPC 关联、消息路由和断线语义。
- 架构决策：正式外部联机前比较“平台原生 TCP”“Server 并行 WSS 监听”和“独立 WSS 网关”。原生 TCP 改动最小但不提供传输加密；正式登录、Token 和玩家数据不得在没有威胁模型与保护方案时直接明文发送。
- 实施边界：不得为了微信客户端替换 Server/Robot 的 TCP，也不得让业务 Handler 依赖微信平台 API；先核对连接、发送、接收、关闭、超时和重连的完整调用链，再确定抽象形状。
- 验证：.NET Server/Robot TCP 回归通过；开发者工具和至少一台目标设备完成正式请求/响应、服务端推送、主动断开、异常断开和重连，消息字节与现有 `PacketCodec` 一致。

### GAME1-PLATFORM-02：正式配置异步加载与启动门禁

- 状态：T3 前计划任务；不阻断 P0 隔离样例和当前本地 Demo。
- 原因：正式客户端启动链为 `GameEntry -> ConfigManager.LoadAll -> SimpleCsvReader.Load -> File.ReadAllLines`，把 `StreamingAssets` 当作本地文件系统并同步阻塞读取；微信小游戏构建中的表通常通过 URL、缓存或平台文件接口取得，P0 只用 `Resources.LoadAsync<TextAsset>` 验证一个独立随包 CSV，不代表正式表加载链已迁移。
- 目标：拆分“异步取得 CSV 字节/文本”和“解析、建索引”，让微信客户端在启动门禁中等待全部表加载成功后再创建 Context、UI 和网络；Server 保留本地构建产物读取，并与客户端复用确定性的解析结果。
- 实施边界：不以阻塞轮询包装异步 API，不为平台复制第二套 CSV，不把小游戏缓存路径硬编码成通用文件路径。
- 验证：Editor、微信开发者工具和至少一台目标设备加载相同表集合并得到一致校验值；缺表、空表、格式错误和网络失败都在业务 Context/UI/网络启动前给出确定失败，Server 配置加载回归通过。

### GAME1-PLATFORM-05：多小游戏平台 WebSocket/WSS 统一传输

- 状态：第二个小游戏平台立项前或 T3 正式外联前计划任务；不阻断已通过的微信局域网 P0。
- 原因：`WX.CreateTCPSocket()` 是微信专用能力，不能直接复用到浏览器或其他小游戏平台。WebSocket 能覆盖连接、二进制收发、推送和长连接，但不同平台仍有 API 包装、前后台生命周期、域名白名单和包体限制差异；公网正式数据还需要 WSS 的证书与终止边界。
- 目标：在 `GAME1-PLATFORM-01` 的平台无关传输契约上增加 WebSocket 适配器；Server 选择并行 WSS 监听或独立 WSS 网关，继续使用现有 `PacketCodec` 二进制协议，不让业务 Handler 感知平台。
- 决策输入：首批目标小游戏平台清单、WSS 在 Server 还是网关终止、受控域名与证书、登录 Token 和玩家数据的威胁模型、各平台后台保活与重连规则。
- 实施边界：不以“都支持 WebSocket”假设 API 和生命周期完全一致；不把本轮局域网明文 TCP 证据当作 WSS、安全或跨平台通过；不替换 Server/Robot 的既有 TCP。
- 验证：浏览器、微信和至少一个新增目标小游戏平台分别完成正式请求/响应、服务端推送、二进制大/小包、主动/异常断开、前后台切换和重连；WSS 证书链、域名白名单与失败日志可诊断，现有 TCP 回归通过。

### GAME1-PROD-04：PlayerEntity 单文档容量治理

- 状态：长期容量任务，外部环境前完成。
- 当前事实：`player_entity` 把邮件和背包等玩家数据嵌入一个 BSON 文档；MongoDB 普通 BSON 单文档硬上限为 16 MiB，不能通过配置、内存、压缩或分片提高。
- 目标：确定低于数据库硬上限的内部预警线和拒绝线，并把所有可增长数据约束为可证明的有界模型。
- 产品决定：确定邮件物理清理与保留数量、有效未领取附件保护、邮箱满时行为、背包 `Capacity` 是否作为硬栈上限，以及邮件字段和附件数量上限。
- 工程范围：BSON 大小观测、写入前容量预检、临界值告警、超限失败处理和文档版本增长预算；若需要无限历史，必须把对应历史数据移出 PlayerEntity 聚合。
- 停止分支：不得在未确认上述产品语义前静默删除有效邮件、拒绝既有合法奖励或改变当前背包超限行为。
- 验证：覆盖预警线、拒绝线、受保护邮箱满、背包临界奖励、文档版本扩展和超限后重登；原始 BSON 大小与业务响应均符合确认口径。
