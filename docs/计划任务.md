# 计划任务

目标读者：AI。

本文件只保存尚未完成的产品决定、功能、工程计划和阶段门禁。已经确认的当前缺陷见 `docs/缺陷列表.md`，未完成验证见 `docs/测试列表.md`，已完成结果见 `docs/工作记录/README.md`。

game1 当前处于本地 Demo/框架验证阶段。未被用户选择的条目只作为 TODO 保留；只在内容制作、外测或上线阶段成立的事项，在阶段切换前不自动进入实现或阻断当前 Demo。

## 使用与收口规则

1. 用户明确选择一个任务 ID 或给出等价的单一目标后，才读取和执行对应任务；其他条目不随之获得授权。
2. 进入任务前读取中枢 `projects/game1/AGENTS.md`、相关 line-kb 和条目列出的事实来源，并重新核对真实项目 Git 现场。
3. 产品语义、协议权威、数据迁移或安全等级未确定时，先给出证据和影响，由用户决定后再实现。
4. 每个任务独立修改和验证；测试会启动服务、进入 PlayMode、创建账号或写入 MongoDB 时，先确认环境和数据授权。
5. 完成后把实际结果写入当月 `docs/工作记录/YYYY-MM.md`，把未执行验证写入 `docs/测试列表.md`，同步更新中枢 line-kb，并从本文件移除该条目。
6. 只有已经存在且对追溯有用的真实提交，才在工作记录中以“关联版本”记录。

## 内容制作、外测或上线前

### GAME1-PROD-01：密码安全迁移

- 状态：外部环境前必须处理。
- 当前事实：`User.Password` 直接存储和比对，无哈希和盐；内网 Demo 暂时接受。
- 目标：确定密码哈希算法、盐、旧明文迁移和登录兼容窗口，不得直接把旧账号变成不可登录状态。
- 验证：新账号不保存明文；旧账号按迁移方案可登录并完成升级；错误密码和重复迁移有可重复测试。

### GAME1-PROD-02：玩家数据耐久性

- 状态：上线前复核。
- 当前事实：`PlayerEntity` 按 60 秒、断线和正常停服批量保存到 `player_entity`；单玩家替换原子，但不同玩家在无序批次中分别成功或失败，Demo 接受崩溃丢失窗口。
- 目标：通过 MongoDB 故障注入确认写入窗口、部分玩家落库、重试、监控和恢复策略是否满足正式数据价值。
- 验证：覆盖写入超时、批次部分玩家失败、进程崩溃和重启恢复，并用 MongoDB 原始文档与告警证据确认实际结果。

### GAME1-PROD-03：正式角色属性来源

- 状态：内容制作或上线前处理。
- 当前事实：`RoleAttributeComponent.SurvivalHp` 只为首次创建 `player_entity` 的角色设置 `Hp/MaxHp=1_000_000_000`，用于稳定 Demo 和自动化；已有玩家数据不会自动迁移。
- 目标：替换为正式角色属性来源并明确已有角色的数据迁移；不得把出生点安全选择隐含进数值修改。
- 验证：新角色、无属性旧角色和已有属性角色分别得到预期数值，迁移可重复执行且不覆盖合法进度。

### GAME1-PROD-04：PlayerEntity 单文档容量治理

- 状态：长期容量任务，外部环境前完成。
- 当前事实：`player_entity` 把邮件和背包等玩家数据嵌入一个 BSON 文档；MongoDB 普通 BSON 单文档硬上限为 16 MiB，不能通过配置、内存、压缩或分片提高。
- 目标：确定低于数据库硬上限的内部预警线和拒绝线，并把所有可增长数据约束为可证明的有界模型。
- 产品决定：确定邮件物理清理与保留数量、有效未领取附件保护、邮箱满时行为、背包 `Capacity` 是否作为硬栈上限，以及邮件字段和附件数量上限。
- 工程范围：BSON 大小观测、写入前容量预检、临界值告警、超限失败处理和文档版本增长预算；若需要无限历史，必须把对应历史数据移出 PlayerEntity 聚合。
- 停止分支：不得在未确认上述产品语义前静默删除有效邮件、拒绝既有合法奖励或改变当前背包超限行为。
- 验证：覆盖预警线、拒绝线、受保护邮箱满、背包临界奖励、文档版本扩展和超限后重登；原始 BSON 大小与业务响应均符合确认口径。
