目标读者：AI。

本文件只保存尚未完成的产品决定、功能、工程计划和阶段门禁。已经确认的当前缺陷见 `docs/缺陷列表.md`，未完成验证见 `docs/测试列表.md`，已完成结果见 `docs/工作记录/README.md`。

## 使用与收口规则

1. 用户明确选择一个任务 ID 或给出等价的单一目标后，才读取和执行对应任务；其他条目不随之获得授权。
2. 进入任务前读取中枢 `projects/game1/AGENTS.md`、相关 line-kb 和条目列出的事实来源，并重新核对真实项目 Git 现场。
3. 产品语义、协议权威、数据迁移或安全等级未确定时，先给出证据和影响，由用户决定后再实现。
4. 每个任务独立修改和验证；测试会启动服务、进入 PlayMode、创建账号或写入 MongoDB 时，先确认环境和数据授权。
5. 完成后把实际结果写入当月 `docs/工作记录/YYYY-MM.md`，把未执行验证写入 `docs/测试列表.md`，同步更新中枢 line-kb，并从本文件移除该条目。
6. 只有已经存在且对追溯有用的真实提交，才在工作记录中以“关联版本”记录。

## 必须先确认方向

### GAME1-DESIGN-01：角色断线重连 Token

- 状态：等待用户决定。
- 当前事实：`RoleDataComponent.LastToken` 标记为 `BsonIgnore`，但 `ReconnectReqHandler` 会从 MongoDB 重新加载组件并校验该字段；当前 Robot 持久化场景使用重新登录，不等同于协议重连。
- 选择：持久化单次 Token、只保证进程内单次有效，或无状态签名 Token。
- 影响范围：`ReconnectReqHandler`、`RoleDataComponent.LastToken`、Token 签发/失效、协议回归和 Robot 重连场景。
- 未确认前：不得修改 Token 持久化或重连成功条件。
- 确认后验证：首次重连、重复使用、过期、伪造、服务重启和重新登录分别符合选定语义。

### GAME1-DESIGN-02：背包 100 格与 UI 64 格

- 状态：等待用户决定。
- 当前事实：服务端背包容量为 100，客户端只创建并刷新 8×8 共 64 个格子；现有布局已于 2026-07-23 修复，但索引 64–99 仍不可见、不可操作。
- 选择：分页、滚动、扩展网格，或调整服务端容量。
- 未确认前：保持现有 64 个可见格，不顺带改变服务端容量或索引 64–99 的呈现方案。
- 确认后验证：第 64、65、100 格的可见性、可操作性和重登恢复符合选定方案，不产生客户端不可访问物品。

### GAME1-DESIGN-03：新手出生点安全

- 状态：等待用户决定。
- 当前事实：实测新角色出生后可能立即受到怪物攻击，当前出生点与野猪生成范围重叠。
- 选择：安全区、调整出生点、调整怪物巡逻/仇恨，或保留当前可受攻击设计。
- 未确认前：不得改地图出生点、怪物配置、巡逻范围和仇恨规则。
- 确认后验证：新角色在目标出生点和预定停留时间内的受击行为符合设计，离开保护范围后的怪物行为不回归。

### GAME1-ENG-05：玩家组件异步加载 Ready 门禁

- 状态：未来技术债务。
- 当前事实：进入游戏链路在 `PlayerOnlineEvent` 完成各模块异步加载前，已经设置 `session.RoleId` 并把 `PlayerEntity` 注册到在线玩家集合；正常客户端会等待 `EnterGameNtf`，但抢跑或异常请求理论上可以在必需组件尚未挂载时进入 `PlayerRpcMessageHandler`。
- 当前约束：`GetComponent<T>()` 表示必需组件，不存在时直接抛出框架状态异常；不得重新在每个业务 Handler 中增加组件判空来掩盖加载窗口。
- 目标：在统一入口建立明确的 Player Ready 状态或调整会话绑定、在线注册与组件加载顺序，使 Player RPC 只在全部必需组件加载完成后可达。
- 主要范围：`PlayerSystem.EnterGameAsync`、`PlayerOnlineEvent` 加载链、`PlayerRpcMessageHandler`、断线与加载失败清理。
- 验证：正常进入、组件加载失败、加载期间抢跑请求、断线、重复进入和重连均不暴露半初始化玩家，也不遗留在线表或 Session 绑定。
