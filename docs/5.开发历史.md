## 客户端网络层重构（2026-05-11）

### 背景

客户端 `NetClient` 自行管理 `TcpClient`/`NetworkStream`/`Thread`，与共享代码中的 `NetworkComponent`+`TcpSession` 存在功能重叠。服务端已使用 `NetworkComponent` 管理连接，客户端应复用同一套基础设施。

### 变更

1. **修复共享代码兼容性**
   - `ShutdownToken.cs`：`GameSynchronizationContext.Instance.Post` → `SynchronizationContext.Current?.Post`（客户端无 GameSynchronizationContext）
   - `NetworkComponent.cs`：`AcceptAsync(CancellationToken)`/`ConnectAsync(string,int)`（.NET 5+）→ `Task.Factory.FromAsync(BeginXxx, EndXxx)`（.NET Framework 4.7.1 兼容）

2. **TcpSession 增加客户端支持**
   - `PostToMainThread`：可选回调，客户端设为 `_mainQueue.Enqueue`，服务端为 null（直接执行）
   - `OnMessageReceived`：可选回调，客户端用于 `MessageDispatcher` 兼容（后续弃用）

3. **客户端 Context**
   - 仿照服务端 `Context` 模式，创建 `Client.Context`
   - 挂载 `NetworkComponent`，通过 `Context.Network` 便利属性访问

4. **NetClient 底层迁移**
   - 原有：`TcpClient.BeginConnect` + `NetworkStream` + `Thread` 接收循环
   - 现：`Context.Network.ConnectAsync(host, port)` → `TcpSession`
   - 消息通过 `TcpSession.ProcessBuffer` → `PostToMainThread` → `Update()` 主线程队列 → `MessageRouter.RouteAsync`

### 关键决策

- **主线程调度**：`TcpSession.PostToMainThread` 回调模式，服务端（null=直接执行）和客户端（投递到主线程队列）行为不同但不影响接口
- **MessageDispatcher 保留**：大量面板仍依赖 `MessageDispatcher.Register<T>`，通过 `TcpSession.OnMessageReceived` 保持兼容，后续统一迁移到 `[MessageHandler]` 属性
- **重连逻辑保留在 NetClient**：`NetworkComponent` 不包含重连逻辑，`NetClient` 通过 `_hadSession` 标记 + `HandlePostDisconnect` 管理

## 阶段九：ECS 重构 Map/Monster/Fight + AOI 完善（2026-05-11）

### 背景

MapPlayer、MapNpc、MonsterUnit、FightUnit 是普通类，不属于 Entity-Component 体系。数据分散、跨模块耦合严重（MonsterSystem 直接调用 Context.Fight/Context.Map，FightSystem 直接调用 Context.Map）。

### 变更

1. **MapObjectEntity 基类**
   - 抽象基类，实现 IMapObject，继承 Entity
   - 便利属性代理到 MapPositionComponent（X, Y, MapId, Line）
   - MapPlayerEntity / MonsterEntity 继承之

2. **MapPlayerEntity（玩家地图投影）**
   - Id = RoleId，是玩家在地图上的运行时投影
   - PlayerRefComponent 桥接回 PlayerEntity（持久化数据）
   - 不替代 PlayerEntity，两者各司其职

3. **MonsterEntity（怪物实体）**
   - 替代原 MapNpc + MonsterUnit 两个类
   - MonsterInfoComponent、MonsterAiComponent、FightUnitComponent 分散数据

4. **FightUnitComponent**
   - 替代 FightUnit 类，挂载在 MapObjectEntity 上
   - 方法（TakeDamage/Heal/AddThreat 等）移至 FightSystem 扩展方法

5. **删除 FightComponent 索引层**
   - 原来 FightComponent.Units 是独立的 objectId→FightUnit 索引
   - 现在 FightUnitComponent 直接挂在 MapObjectEntity 上，通过 FindMapObject 查找
   - Context.Fight 属性删除，FightSystem 不再依赖 FightComponent

6. **AOI 完善**
   - 代码从 server/Core/Aoi/ 迁移至 client/Assets/Scripts/shared/Core/Aoi/（后又迁回 server/Core/Aoi/，命名空间改为 Game.Core.Aoi）
   - 新增一站式 API：AddAoiEntity/RemoveAoiEntity/UpdateAoiEntity
   - 修复观察者跨塔视野差集（GetWatcherTowerChange）
   - 实现 MapAoiNotifier.OnWatcherUpdate（玩家跨塔移动时视野自动更新）

7. **怪物 ObjectType 修正**
   - 原来 Monster 在地图上以 Npc(2) 类型存在
   - 现在修正为 Monster(3)，客户端需适配

### 删除文件

| 文件 | 替代 |
|------|------|
| MapPlayer.cs | MapPlayerEntity |
| MapNpc.cs | MonsterEntity |
| MonsterUnit.cs | MonsterEntity + MonsterInfoComponent + MonsterAiComponent |
| FightUnit.cs | FightUnitComponent |
| FightComponent.cs | 删除索引层 |

### 关键决策

- **PlayerEntity 不入地图**：PlayerEntity 管理持久化数据，MapPlayerEntity 是运行时投影，通过 PlayerRefComponent 桥接
- **FightComponent 全删**：不保留索引层，所有战斗单元查找走 MapComponent.FindMapObject → FightUnitComponent
- **AOI 一站式 API**：合并对象+观察者操作，业务代码不再分别调用 AddObject+AddWatcher

## 阶段十：Logic/View 分离（2026-05-18 已完成）

### 背景

当前客户端所有代码编译为单一 `Assembly-CSharp.dll`，业务逻辑（Handler）与 UI（Panel）混杂在同一目录。缺乏自动化测试手段，调试依赖 Unity Editor 运行。

### 决策变化

原计划用 .asmdef 实现程序集隔离（Shared → Logic → View），实际实施中发现：
- 客户端代码兼容 .NET 4.7.1，Shared 代码用了 C# 9 特性（target-typed new、GetValueOrDefault）
- Shared 代码用了 C# 9 特性（target-typed new、GetValueOrDefault），Robot.csproj 需用 net8.0
- 最终改为 **纯目录分离**（无 .asmdef），Logic/ 代码零 UnityEngine 依赖，可被 Robot.csproj 直接 Compile Include 引用

### 实施内容

1. **Logic/ 目录**（零 UnityEngine 依赖）
   - `IClientUI.cs` — UI 桥接接口 + ClientContext
   - `IPanels.cs` — 面板接口（ILoginPanel, IRoleSelectPanel, IBagPanel, IMailPanel, ITaskPanel, IMainPanel）
   - `Handlers/` — 7 个 Handler（Login/RoleSelect/Bag/Mail/Task/Chat/Fight）
   - `Data/` — GameData, MapObjectType

2. **View/ 目录**（Unity 表现层）
   - `Core/` — 框架（UIManager, UIPanel, UIBuilder, GameEntry, Context 等）
   - `Panels/` — 面板（LoginPanel, BagPanel, MainPanel 等 9 个）
   - `Scene/` — 场景对象（PlayerController, MapGround, MonsterView 等 9 个）
   - `Network/` — NetClient
   - `Editor/` — SceneCreator

3. **解耦机制**
   - Handler 不再直接 `UIManager.Instance?.GetPanel<T>()`，改用 `ClientContext.UI?.GetPanel<T>()`
   - Panel 实现对应 IPanel 接口
   - UIManager 实现 IClientUI
   - GameEntry 启动时注入：`ClientContext.UI = UIManager.Instance`

4. **Robot 引用方式**：Robot.csproj 通过 Compile Include 直接引用 shared/**/*.cs 和 Logic/**/*.cs，无需中间 .csproj

### 踩坑记录

| 问题 | 解决 |
|------|------|
| .asmdef 导致程序集分离，View 引用 Logic 的接口、Logic 引用 View 的 Panel 类型形成循环 | 删除全部 .asmdef，恢复单 Assembly-CSharp 编译 |
| Logic.csproj 编译产物 bin/obj 被 Unity 当作预编译 DLL | 删除 bin/obj 目录，加入 .gitignore |
| 删除 .asmdef 后 .meta 残留 | 手动清理 Logic.asmdef.meta 等 |
| shared 代码用了 C# 9 target-typed new、GetValueOrDefault 等 | Robot.csproj 使用 net8.0 |
| 命名空间变更后 `Login.LoginPanel` 不存在 | 改为 `LoginPanel`（同 namespace Client.View） |
| 迁移后 GameData/MapObjectType 找不到 | 添加 `using Client.Logic;` |
