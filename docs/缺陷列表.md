## 使用与收口规则

1. 进入任务前读取中枢 `projects/game1/AGENTS.md`、相关 line-kb 和条目列出的事实来源。
2. 在真实项目重新核对分支、远端和完整脏工作区，不使用历史工作记录判断当前现场。
3. 修复前先复现，或用当前代码、配置、协议和日志证明根因；产品语义未确定时停止并转入计划任务讨论。
4. 每个任务独立修改和验证；测试会启动服务、进入 PlayMode、创建账号或写入 MongoDB 时，先确认环境和数据授权。
5. 完成后把实际结果写入当月 `docs/工作记录/YYYY-MM.md`，把未执行验证写入 `docs/测试列表.md`，同步更新中枢 line-kb，并从本文件移除该条目。
6. 只有已经存在且对追溯有用的真实提交，才在工作记录中以“关联版本”记录。

## 当前缺陷

### GAME1-NET-01：TCP 会话释放竞争

- 状态：待处理。
- 事实：Robot 主动断线时可稳定出现 `Stream does not support writing`。`OnSessionDisconnected` 会在 `ReceiveLoopAsync` 完全退出前释放 `_packetBuffer`，接收循环可能继续写入或整理已释放的缓冲区。
- 目标：明确 Socket、接收循环和 `_packetBuffer` 的释放所有权与完成顺序，消除主动断线异常。
- 主要范围：`client/Assets/Scripts/shared/Core/Network/TcpSession.cs`、`NetworkComponent.cs`；不得重新引入 `SessionDispatcher`、消息二次 `Post` 或客户端专用释放层。
- 验证：重复主动断线不再出现接收异常；`login_test`、`task_persistence_test`、正常 Ctrl+C 停服和受影响项目构建通过；客户端与 Robot 会话行为无回归。

### GAME1-DATA-01：过期物品和邮件未清理

- 状态：待处理。
- 事实：`BagItem` 与 `RoleMail` 都保存 `ExpireTime`，当前仅在邮件查询时过滤过期邮件，没有统一的登录或定时物理清理。
- 目标：确定并实现 `ExpireTime` 的权威时间单位、触发点和物理清理策略。
- 主要范围：`server/Components/Bag/BagItem.cs`、`server/Components/Mail/RoleMail.cs` 及对应组件系统。
- 停止分支：物品过期补偿、邮件附件处理或离线清理责任未定义时，先转入产品语义确认。
- 验证：覆盖边界时间、登录清理、定时清理、重登恢复以及带未领取附件的过期邮件。

### GAME1-BAG-02：容量辅助方法忽略需求格数

- 状态：Demo 低优先级。
- 事实：`RoleBagSystem.HasSpace(int need)` 忽略 `need`，只判断是否至少存在一个空格；当前没有调用方，邮件整批预检也不依赖该方法。
- 目标：出现真实调用需求时按所需空格数实现，或确认无业务概念后删除该辅助方法，避免未来误用。
- 验证：覆盖需求为 0、1、剩余格数、剩余格数加 1，以及容量边界外的异常输入。

### GAME1-UI-03：任务面板控件轻微重叠

- 状态：Demo 视觉微调。
- 事实：`TaskPanel` 的任务 ID 输入框与接取按钮边缘存在 5 px 几何重叠；当前显示和中心点击路径不受阻。
- 目标：在后续统一视觉整理时消除重叠，不改变任务业务或已修复的底栏位置。
- 验证：1920×1080 PlayMode 中控件无重叠、均位于卡片内，中心 EventSystem 命中和交互状态正确。
