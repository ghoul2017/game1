# 缺陷列表

目标读者：AI。

本文件只保存已经由当前代码、日志或实测确认且尚未修复的缺陷。未完成功能、产品决定、工程计划和阶段门禁见 `docs/计划任务.md`，未完成验证见 `docs/测试列表.md`，已完成结果见 `docs/工作记录/README.md`。

game1 当前已具备本机联机技术测试版本。列表中的事项不自动获得优先级或执行授权；用户选择任务 ID 或给出
等价目标后，才进入调查和修改。

## 使用与收口规则

1. 进入任务前读取中枢 `projects/game1/AGENTS.md`、相关 line-kb 和条目列出的事实来源。
2. 在真实项目重新核对分支、远端和完整脏工作区，不使用历史工作记录判断当前现场。
3. 修复前先复现，或用当前代码、配置、协议和日志证明根因；产品语义未确定时停止并转入计划任务讨论。
4. 每个任务独立修改和验证；测试会启动服务、进入 PlayMode、创建账号或写入 MongoDB 时，先确认环境和数据授权。
5. 完成后把实际结果写入当月 `docs/工作记录/YYYY-MM.md`，把未执行验证写入 `docs/测试列表.md`，同步更新中枢 line-kb，并从本文件移除该条目。
6. 只有已经存在且对追溯有用的真实提交，才在工作记录中以“关联版本”记录。

## 当前缺陷

### GAME1-TOOL-01：本地启动器就绪判断没有绑定监听所有权

- 状态：待处理；停止/强杀路径的进程所有权复核正常，缺陷只在启动完成判断。
- 事实：`LocalTestServerWindow.PrepareStart` 只在启动前探测一次 9000；`UpdateServerStart` 随后只确认自有进程存活，
  再用普通 TCP 连接判断任意监听者存在，就显示“本地服务端已就绪”并可进入 Play。
- 影响：未知进程若在 Server 完成 MongoDB 初始化和端口绑定前抢占 9000，客户端可能连接错误服务；自有 Server
  稍后才会因绑定失败退出。这违背工具“不接管未知监听者”的安全边界。
- 目标：实施 `GAME1-ENG-12` 的 token/PID/端点 ready 握手，端口探测不再单独构成就绪证据。
- 验证：`TEST-LOCAL-SERVER-OWNERSHIP-01`。

### GAME1-DOC-01：完整交付报告引用的关键运行证据已缺失

- 状态：待处理；受管测试的四份现存 TRX 可复核，缺失范围是 Unity PlayMode 与真实 Robot 的部分运行证据。
- 事实：报告引用的 `client/Temp/CodexValidation/playmode-final-movement.xml` 和 `.log` 当前不存在；Arena Robot
  `1/1` 只记录为已经清理的临时 stdout。现存 Server 日志只能证明账号、进角和部分业务日志，不能证明全部断言。
- 影响：`14/14` PlayMode、Arena 幂等/回放和 Robot 负向检查无法从报告列出的路径独立复核。
- 目标：实施 `GAME1-ENG-13`；在新证据产生前，报告必须区分“现存可复核”与“当时运行、原始证据未保留”。
- 验证：`TEST-DELIVERY-EVIDENCE-01`。

### GAME1-NET-02：Player 未 Ready 的统一拒绝包络

- 状态：待处理；会话所有权、重复入场和陈旧连接授权已于 2026-08-01 修复，剩余问题是协议错误表达。
- 当前事实：`PlayerSystem.EnterGame` 只有在完整加载且复核 session 仍为当前用户连接后才原子绑定；同一连接只允许
  同角色幂等重入，切角被拒绝。Player RPC/Ntf 还会核验 `PlayerOnline.Session`，陈旧连接不能进入业务。
- 剩余缺陷：Player 尚未 Ready 或 session 已失效时，`PlayerRpcMessageHandler` 只向名为 `ErrorMessage` 的属性写错；
  `BagUseItemAck` 使用 `Error`，部分响应没有错误字段，仍可能返回默认形状并被客户端误判成功。
- 目标：建立覆盖所有 Player RPC 响应类型的确定拒绝语义；未 Ready 请求不能进入业务，也不能返回看似成功的默认包。
- 停止分支：若需要公共错误包、修改 RPC 包络或统一响应协议，先核对客户端请求关联与各响应的真实消费链；
  不继续增加基于属性名的反射分支。
- 验证：首次进入期间流水发送至少覆盖 `ErrorMessage`、`Error` 和无错误字段三类 Player 请求；全部得到可识别拒绝，
  Ready 后同一批请求恢复正常语义。对应回归为 `TEST-PLAYER-READY-01`。

### GAME1-FIGHT-01：旧地图战斗状态、复活和怪物广播未闭环

- 状态：待处理；影响旧地图/Fight 链，不阻断独立的远征 GameplayCore。
- 事实：玩家进图时把 `RoleAttributeComponent` 复制为地图 `FightAttribute`，之后两者不再同步。战斗伤害修改
  FightAttribute，药品和升级修改 RoleAttribute，物品复活又绕过 `FightHelper.Revive` 直接修改 FightAttribute。
- 关联缺陷：客户端“回城复活”只重发 `EnterMapReq`，不会恢复死亡战斗单元；`BroadcastToAoiWatchers`
  只能按玩家 ID 找地图，怪物主动攻击和怪物死亡广播失败；死亡 DeltaHp 恒为 0，`KilledByNtf.IsMonster`
  按受害者类型赋值而客户端按击杀者类型读取。
- 影响：旧地图链中的玩家 HP、持久化属性、死亡/复活和客户端战斗表现可能互相不一致。
- 目标：先确定旧地图链是否继续作为产品入口；若继续，明确战斗 HP 权威、保存边界和复活语义，再分别修复广播查图与通知字段。
- 停止分支：是否把在线战斗 HP 回写持久化属性属于产品和数据语义，未决定前不得用双写或离图覆盖掩盖问题。
- 验证：覆盖怪物攻击玩家、玩家死亡、重进图、物品复活、离图重建和断线保存；核对服务端内存、通知字段、客户端表现和重登数据。

### GAME1-MAP-01：旧地图坐标请求缺少完整权威校验

- 状态：待处理；影响旧地图移动和切图请求。
- 事实：`MapMoveReq` 只校验目标坐标位于地图边界内，不校验单次位移、速度或路径；`ChangeMapReq`
  接受任意正数 X/Y，进入目标地图前没有边界检查。
- 影响：客户端可以在同一地图内跳到任意合法坐标，也可以通过切图请求把玩家放到目标地图边界之外。
- 目标：区分正常移动、主动传送和服务端被动传送入口，为每类入口定义权威坐标来源和校验。
- 验证：覆盖合法移动、跨格跳跃、超速、负数/边界坐标、超界切图和服务端被动传送，并确认 AOI 与客户端纠正一致。

### GAME1-MONSTER-01：旧地图怪物刷新计时到期后不复位

- 状态：待处理；影响旧地图 Monster 链。
- 事实：同地图同配置怪物共用一个 `mapId_line_cfgId` 刷新时间，多只死亡会覆盖该时间；
  `CheckSpawnTimers` 到期后调用 `SpawnMonster`，但不清零或重排计时。
- 影响：到期后 AI 每秒持续尝试生成，达到 MaxCount 后仍继续空尝试；多只连续死亡也不能逐只计时。
- 目标：先确定逐只刷新还是按缺口补齐，再让计时状态在刷新成功、达到上限和配置缺失时都有确定收口。
- 验证：覆盖同配置多只连续死亡、计时到期、达到 MaxCount、配置缺失和长时间运行，确认生成数量与计时器状态稳定。

### GAME1-CHAT-01：旧聊天 UI 的私聊入口不可用

- 状态：待处理；协议正向私聊可由 Robot 或临时协议客户端使用。
- 事实：客户端提供“私聊”频道按钮，但 `ChatController.SendChat` 不填写 `ChatReq.TargetName`；服务端会返回
  “无效的私聊目标”。合法私聊只推送给接收方，不回显给发送方。
- 影响：真实 UI 无法完成私聊，发送者也没有成功消息的本地或服务端回显。
- 目标：确定目标选择/输入和发送方展示语义，再接通客户端请求与回归。
- 验证：两个客户端覆盖目标为空、自己、离线和在线目标，确认发送方/接收方展示与服务端错误一致。

### GAME1-PLAYER-01：旧角色成长字段和客户端属性表现未闭环

- 状态：待处理；影响旧角色列表、旧地图 UI 和通用成长通知。
- 事实：等级同时存在于 `UserRole.Level`、`RoleDataComponent.Level` 和 `RoleAttributeComponent.Level`，经验存在于
  RoleData 和 RoleAttribute；实际经验与升级只修改 RoleAttribute。`EnterGameNtf` 不含当前属性快照，客户端也没有
  Exp、Gold、LevelUp、ItemGain 和 Mp 通知 Handler，旧 MainPanel 使用固定经验、金币和钻石文本。
- 影响：登录角色列表、入场等级、战斗属性和客户端成长表现可能长期显示不同状态。
- 目标：确定角色列表投影、身份资料和成长属性的权威来源及同步方向，再处理既有 PlayerEntity/UserRole 数据和客户端快照/增量模型。
- 停止分支：权威字段和既有数据迁移未决定前，不增加第三套同步字段或只在客户端修饰显示。
- 验证：覆盖新角色、已有角色、经验升级、怪物奖励、断线保存和重登，核对 MongoDB 原始文档、登录列表、入场通知和 UI。

### GAME1-DATA-01：过期邮件未清理

- 状态：待处理。
- 事实：`RoleMail` 保存 ExpireTime，当前仅在邮件列表和未读统计中过滤过期邮件，没有统一的登录或定时物理清理。
- 关联缺陷：已读、附件领取和删除 Handler 按 MailId 直接访问字典，不检查 `IsExpired`；知道 ID 的客户端仍可操作隐藏邮件。隐藏邮件继续留在字典和 `player_entity` BSON 中；`MaxVisibleMailCount=100` 只限制查询结果，不限制存储增长。
- 已确认边界：当前 UID 背包保留 `BagItem.ExpireTime`，并明确把它作为普通堆叠元数据，不比较当前时间、不作废也不清理；背包侧不属于本缺陷。
- 目标：确定并实现邮件 ExpireTime 的权威时间单位、触发点、按 ID 操作规则、保留数量和物理清理策略。
- 主要范围：`server/Components/Mail/RoleMail.cs` 及邮件组件系统。
- 停止分支：邮件附件处理或离线清理责任未定义时，先转入产品语义确认。
- 验证：邮件覆盖边界时间、按 ID 已读/领取/删除、查询上限、BSON 体积、登录清理、定时清理、重登恢复以及带未领取附件的过期邮件；不得借本缺陷改变 BagItem 的当前普通元数据语义。
