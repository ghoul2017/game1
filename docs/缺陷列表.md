## 当前缺陷

### GAME1-NET-01：TCP 会话释放竞争

- 状态：待处理。
- 事实：Robot 主动断线时可稳定出现 `Stream does not support writing`。`OnSessionDisconnected` 会在 `ReceiveLoopAsync` 完全退出前释放 `_packetBuffer`，接收循环可能继续写入或整理已释放的缓冲区。
- 目标：明确 Socket、接收循环和 `_packetBuffer` 的释放所有权与完成顺序，消除主动断线异常。
- 主要范围：`client/Assets/Scripts/shared/Core/Network/TcpSession.cs`、`NetworkComponent.cs`；不得重新引入 `SessionDispatcher`、消息二次 `Post` 或客户端专用释放层。
- 验证：重复主动断线不再出现接收异常；`login_test`、`task_persistence_test`、正常 Ctrl+C 停服和受影响项目构建通过；客户端与 Robot 会话行为无回归。

### GAME1-NET-02：EnterGame 未 Ready 与重复进入会话边界

- 状态：待处理；由当前代码确认，尚未执行并发运行时复现。
- 事实：首次进入且 `session.RoleId == 0` 时，`PlayerSystem.EnterGame` 在完整加载后才设置 RoleId 并把
  `PlayerEntity` 加入在线索引，因此早到的玩家请求不会取得半加载实体，也不会进入具体业务 Handler。但
  `PlayerRpcMessageHandler` 找不到玩家时只尝试写入名为 `ErrorMessage` 的响应属性；`BagUseItemAck` 使用
  `Error`，`PkModeChangedNtf` 等响应没有错误字段，这些请求会收到默认形状的响应，客户端可能把它当成成功。
- 重复进入事实：`EnterGameReqHandler` 没有拒绝已有 RoleId 的会话，也没有进入中状态。重复进入或切换角色的
  查询/加载期间，旧 `session.RoleId` 仍可命中旧玩家并执行玩家业务；切换到不同角色后，`AddPlayer` 只替换
  相同 RoleId，旧角色还可能保留在在线索引中。
- 目标：建立显式的 EnterGame 进入中/Ready 会话边界和覆盖所有 Player RPC 响应类型的确定拒绝语义；
  未 Ready 请求不能进入业务或修改玩家状态，重复进入不能在旧角色上继续处理请求或留下幽灵在线实体。
- 停止分支：先决定同一会话的再次 `EnterGameReq` 应稳定拒绝，还是支持原子切换角色；若需要新增公共错误包、
  修改 RPC 包络或统一响应协议，再核对客户端请求关联和通知型响应的真实消费链，不直接用反射增加更多字段名
  分支。
- 验证：首次进入期间并发或流水发送至少覆盖 `ErrorMessage`、`Error` 和无错误字段三类响应的玩家请求；
  再覆盖重复进入同一角色和切换不同角色。所有路径符合确认后的拒绝/切换语义，不误报成功、不修改错误角色，
  在线索引和会话只保留目标角色；Ready 后同一批请求恢复正常语义。对应回归为
  `TEST-PLAYER-READY-01`。

### GAME1-DATA-01：过期邮件未清理

- 状态：待处理。
- 事实：`RoleMail` 保存 ExpireTime，当前仅在邮件查询时过滤过期邮件，没有统一的登录或定时物理清理。
- 已确认边界：当前 UID 背包保留 `BagItem.ExpireTime`，并明确把它作为普通堆叠元数据，不比较当前时间、不作废也不清理；背包侧不属于本缺陷。
- 目标：确定并实现邮件 ExpireTime 的权威时间单位、触发点和物理清理策略。
- 主要范围：`server/Components/Mail/RoleMail.cs` 及邮件组件系统。
- 停止分支：邮件附件处理或离线清理责任未定义时，先转入产品语义确认。
- 验证：邮件覆盖边界时间、登录清理、定时清理、重登恢复以及带未领取附件的过期邮件；不得借本缺陷改变 BagItem 的当前普通元数据语义。
