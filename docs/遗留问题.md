# 遗留问题

目标读者：人类。

2026-07-15 的项目接手、现场收口、可重复基线和玩家批量持久化已经完成。以下事项不属于本次接手收口范围，应按独立目标处理；其中产品选择在确认前不得由实现人员自行决定。

## 需要产品或架构决定

### 角色断线重连的 Token 语义

`RoleDataComponent.LastToken` 标记为 `BsonIgnore`，但 `ReconnectReqHandler` 会从 MongoDB 重新加载组件并校验该字段。带角色 ID 的 Token 在断线后无法恢复匹配；当前 Robot 的持久化测试通过重新登录验证，不等同于协议重连测试。

后续必须先决定 Token 是持久化的单次凭证、只保证进程内单次有效，还是只依赖签名和过期时间的无状态凭证，再实现和测试相应状态机。

### 新手出生点是否为安全区

测试记录显示新角色出生后可能立即受到怪物攻击。该现象既可能违反新手保护设计，也可能是当前 Demo 的预期行为。确认前不得调整出生点、怪物巡逻范围或仇恨规则。

### 背包容量与 UI 可见格数

服务端背包容量为 100，当前客户端网格只展示 8×8 共 64 格。布局偏移属于明确缺陷，但容量应分页、滚动、扩展网格还是收窄服务端容量属于产品选择，需要和布局修复分开决定。

### 新角色默认 10 亿 HP

项目当前处于 Demo/框架阶段。`RoleAttributeComponent.SurvivalHp` 将新建角色的 `Hp/MaxHp` 默认设为 `1_000_000_000`，用于避免测试角色被环境怪物快速击杀，从而稳定框架和自动化验证。

- 该默认值只作用于首次创建 `RoleAttributeComponent` 的角色；已有 MongoDB 属性记录不会自动迁移。
- 这是明确保留的 Demo 测试语义，不代表正式数值设计，也不能据此认定新手出生点允许或不允许怪物攻击。
- 进入内容制作或正式数值阶段前，必须改为正式角色属性来源，并单独确认出生点、怪物巡逻和仇恨范围。

### 玩家数据批量保存边界

在线玩家组件已按 60 秒定时、断线和正常停服批量保存，并按组件集合分别执行 `BulkWrite`。业务只同步修改内存和标脏。

- 进程崩溃仍可能丢失上一成功批次之后的变更。
- 任务、背包、邮件和属性分集合保存，不提供跨集合原子性；异常退出可能形成部分落库。
- 当前 Demo/框架阶段接受该取舍，上线前需结合数据价值、恢复策略和监控重新评估。

## 已确认缺陷

### TCP 会话释放竞争

Robot 主动断线时可稳定出现 `Stream does not support writing`。当前链路会在 `ReceiveLoopAsync` 完全退出前由 `OnSessionDisconnected` 释放 `_packetBuffer`，接收循环可能继续写入或整理已释放的缓冲区。现有业务断言不受影响，但网络生命周期所有权尚未闭环。

### 物品效果配置键不匹配

`ItemEffectSystem` 使用物品 `ConfigId` 查询 `ItemEffectConfig`，但配置表主键是效果 `Id`，物品关联字段是 `ItemId`。当前表中效果 ID 为 1–5、物品 ID 为 2001–2005，因此消耗品可能已经扣除但没有应用对应效果。

另有独立配置语义待确认：`ItemConfig.csv` 将物品 `2005` 定义为复活卷轴，但 `ItemEffect.csv` 对应行仍使用 `EffectType=1`。修复查询键时不得顺带替产品选择该效果语义。

### 邮件附件领取可能丢失物品

领取邮件会先把邮件标记为已领取，再逐项调用背包 `AddItem`，但没有在变更前聚合校验容量，也没有处理部分添加失败。背包不足时可能出现邮件已领取而附件未完整到账。该问题与邮件、背包分集合保存不要求原子性是两个不同层级：后续至少需要保证单次内存业务的完整校验和提交顺序。

### Unity UI 布局

- MailPanel 和 TaskPanel 的底部控件在目标分辨率下可能越出画面。
- BagPanel 的 8×8 网格明显偏右下，部分格子超出或贴近卡片边界。

布局修复需要使用 Unity 2022.3.62f3 在目标分辨率下复现和验证；背包容量呈现按前述产品决定另行处理。

### 物品和邮件过期数据未清理

`BagItem` 与 `RoleMail` 都有 `ExpireTime`，当前仅在邮件查询时过滤过期邮件，没有统一的定时或登录清理，过期数据会继续留在持久化集合中。

### 安全：密码明文存储

`User.Password` 直接存储和比对，无哈希和盐。内网 Demo 可以继续使用，进入外部测试或生产环境前必须设计密码迁移和安全存储。

## 功能与工程债务

### 离线系统邮件

当前仅支持在线玩家组件上的邮件操作，没有离线系统邮件、全服邮件队列或玩家可用的系统邮件生成入口。邮件正向测试需要预置数据或专用 Robot/测试工具。

### Monster AI 已知局限

1. **单目标仇恨**：AI 只追踪一个目标，`ThreatMap` 未接入，无法实现仇恨转移
2. **巡逻无路径**：`PatrolTarget` 为随机点，无固定巡逻路线
3. **攻击后回 Idle**：攻击完立即重置状态而非持续攻击，行为略显机械
4. **无脱战回血**：怪物脱离战斗后不会回血，下次被攻击时仍是残血

### 自动化和工程入口

- Robot 当前只覆盖登录和任务持久化；独立背包、邮件、聊天、AOI 和协议重连仍缺自动化场景。
- 项目缺少根 README、CI 和常规 C#/Unity 测试。
- `scripts/check-all` 的缺失 Unity 项目提示仍引用旧版 Unity 2021.3.26f1c1，当前项目版本是 2022.3.62f3。
- 当前全解决方案构建仍有既有的客户端未等待调用警告和服务端可空引用警告，应按模块独立消化，不能与功能修复混做。
