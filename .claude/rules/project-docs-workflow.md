# Docs 工作流：需求 → 计划 → 任务

启动对话时，检查 `docs/1.需求.md` 是否有未规划条目，有则自动拆解。

## 流程

```
1.需求.md          用户写需求（编号列表）
       ↓
2.PLAN/{编号}-{名称}.md   我生成详细计划（类名、方法签名、文件路径）
       ↓
3.TODO.md          我拆解为可勾选任务清单
       ↓
审批               用户确认计划
       ↓
实现                按 TODO 逐项执行，完成后勾选
```

## 1. 需求格式

`docs/1.需求.md` 使用编号列表，每条一个需求：

```markdown
1. 需求描述文字
2. 另一个需求
```

已规划的需求会标注状态：

```markdown
1. [已规划] 已拆解的需求
2. 待规划的新需求
```

## 2. 计划格式

文件名：`docs/2.PLAN/{编号}-{简短名称}.md`

```markdown
# {需求标题}

## 概述
{目标，一两句话}

## 新增文件

### {命名空间}.{类名} — {相对路径}
- 用途：{一句话}
- 基类/接口：{继承/实现什么}
- 字段：
  - `Type FieldName` — 说明
- 方法：
  - `public ReturnType MethodName(ParamType param)` — 说明

## 修改文件

### {相对路径}: {类名}
- 变更类型：新增/修改/删除
- 新增方法：`签名` — 说明
- 修改方法：`旧签名 → 新签名` — 原因
- 删除方法：`签名` — 原因

## 消息定义（如涉及）

| MsgId | 消息类 | 方向 | 关键字段 |
|-------|--------|------|----------|
| {id}  | XxxReq | C→S  | ...      |
| {id}  | XxxRes | S→C  | ...      |

## 数据库变更（如涉及）

- 新增集合：`{collection_name}`，文档类 `{ClassName}`
- 修改文档：`{ClassName}` 增加字段 `FieldName`

## 执行顺序

1. {先做什么}
2. {再做什么}
3. ...

## 验证

- [ ] 编译通过
- [ ] {功能验证点}
```

## 3. TODO 格式

`docs/3.TODO.md` 按需求分组，粗粒度任务清单，只列做什么不列怎么做（细节在 Plan 里）：

```markdown
## {编号}: {需求标题}

- [ ] 新增 XxxComponent + XxxSystem
- [ ] 新增 XxxHandlers + 消息定义
- [ ] 修改登录流程，挂载新 Component
- [ ] 客户端对接
```

任务完成后勾选 `[x]`。需求全部完成时在 `1.需求.md` 标注 `[已完成]`。

## 启动检查

对话开始时：

1. 读 `docs/1.需求.md`
2. 找出未标注 `[已规划]` 的编号条目
3. 逐条生成计划文件到 `docs/2.PLAN/`
4. 更新 `docs/3.TODO.md`
5. 回 `docs/1.需求.md` 将该条目标注为 `[已规划]`

## 注意

- Plan 是详细设计文档，必须具体到类名、方法签名、文件路径、字段类型，不含糊
- TODO 是粗粒度清单，只列"做什么"（如"新增背包系统"、"客户端对接"），不重复 Plan 的细节
- 遵循项目现有架构约定（ECS 分层、Handler 风格、消息命名等）
- 如需求不明确，在需求文件里提问
