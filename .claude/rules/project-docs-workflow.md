# Docs 工作流：需求 → 计划 → 任务

启动对话时，检查 `docs/1.需求.md` 是否有未规划条目，有则自动拆解。同时检查 `docs/4.发现需求.md` 是否有待解决项。

## 流程

```
1.需求.md          用户写需求（# 标题 + ## 描述）
       ↓
2.PLAN/{编号}-{名称}.md   我生成详细计划（类名、方法签名、文件路径）
       ↓
3.TODO.md          我拆解为可勾选任务清单
       ↓
审批               用户确认计划后才能开始实现
       ↓
实现                按 TODO 逐项执行，完成后勾选

4.发现需求.md       自行发现的问题（如环境缺失、标记遗漏），自行规划、自行解决
```

**关键约束：计划生成后必须等用户确认才能开始实现。** 不等审批就动手 = 违规。

## 1. 需求格式

`docs/1.需求.md` 使用 `#` 标题 + `##` 描述格式：

```markdown
# 需求标题
## 需求详细描述文字
## 补充说明（可多行）
```

状态标记位置：
- **`[已审批]`** 和 **`[已完成]`** 标在 `#` 标题行
- **`[已规划]`** 标在 `##` 描述行（规划是补充的，可能有多行）

```markdown
# [已审批] [已完成] 已完成的需求
## [已规划] 已拆解的描述
## 补充说明

# 新需求（无标记 = 待规划）
## 描述文字

# [已审批] 已审批的需求
## [已规划] 已规划的描述
```

## 2. 计划格式

文件名：`docs/2.PLAN/{编号}-{简短名称}.md`

```markdown
# {需求标题}

## 概述
{目标，一两句话}

## 新增文件

### {命名空间}.{类名} — {相对路径}
- 用途：{一句话}
- 基类/接口：{继承/实现什么}
- 字段：
  - `Type FieldName` — 说明
- 方法：
  - `public ReturnType MethodName(ParamType param)` — 说明

## 修改文件

### {相对路径}: {类名}
- 变更类型：新增/修改/删除
- 新增方法：`签名` — 说明
- 修改方法：`旧签名 → 新签名` — 原因
- 删除方法：`签名` — 原因

## 消息定义（如涉及）

| MsgId | 消息类 | 方向 | 关键字段 |
|-------|--------|------|----------|
| {id}  | XxxReq | C→S  | ...      |
| {id}  | XxxRes | S→C  | ...      |

## 数据库变更（如涉及）

- 新增集合：`{collection_name}`，文档类 `{ClassName}`
- 修改文档：`{ClassName}` 增加字段 `FieldName`

## 执行顺序

1. {先做什么}
2. {再做什么}
3. ...

## 验证

- [ ] 编译通过
- [ ] {功能验证点}
```

## 3. TODO 格式

`docs/3.TODO.md` 按需求分组，粗粒度任务清单，只列做什么不列怎么做（细节在 Plan 里）。粒度为"模块"或"子系统"级别，不要拆到单个文件或单个方法：

```markdown
## TODO：

- [ ] 1: 去掉冗余 LoadAsync 调用 steps1 背包模块改造
- [ ] 1: 去掉冗余 LoadAsync 调用 steps2 邮件/任务/怪物模块适配
```

任务完成后勾选 `[x]`。需求全部完成时在 `1.需求.md` 的 `#` 标题行标注 `[已完成]`。

## 4. 发现需求格式

`docs/4.发现需求.md` 记录自行发现的问题（环境缺失、标记遗漏、改进机会等），格式同 `1.需求.md`：

```markdown
# 发现的问题标题
## [已规划] 问题描述
## [已规划] 解决方案说明
```

- 无需审批，自行规划、自行解决
- 解决后在 `#` 标题行标注 `[已完成]`
- `##` 描述行同样使用 `[已规划]` 标记

## 启动检查

对话开始时：

1. 读 `docs/1.需求.md`
2. 找出 `##` 描述行未标注 `[已规划]` 的需求
3. 逐条生成计划文件到 `docs/2.PLAN/`
4. 更新 `docs/3.TODO.md`
5. 回 `docs/1.需求.md` 在该需求的 `##` 描述行标注 `[已规划]`
6. **等待用户审批后再开始实现**

## 注意

- Plan 是详细设计文档，必须具体到类名、方法签名、文件路径、字段类型，不含糊
- TODO 是粗粒度清单，只列"做什么"（如"新增背包系统"、"客户端对接"），不重复 Plan 的细节
- TODO 不写"编译验证"、"测试"等执行侧事项，由实现者自行判断
- 遵循项目现有架构约定（ECS 分层、Handler 风格、消息命名等）
- 如需求不明确，在需求文件里提问
- `1.需求.md` 已有文字不修改，但允许追加状态标记（`[已规划]`/`[已审批]`/`[已完成]`）
- **标 `[已完成]` 前必须检查所有 `##` 描述行是否都有 `[已规划]` 标记**——有遗漏说明该需求未完整规划或实现
