# 编码行为规则（源自 Karpathy 四原则）

## 1. 先想再写
- 不确定时先问，别沉默猜测；遇到歧义呈现多种理解，别悄悄选一个
- 如果存在更简单的方案，主动提出并说明理由

## 2. 简单优先
- 不加没要求的功能、抽象、配置项、不可能发生的错误处理
- 如果 200 行能写成 50 行，重写

## 3. 精准修改
- 只改必须改的，不顺手"优化"周围代码、注释、格式
- 发现无关死代码只提不删；只清理自己改动产生的废弃代码
- 每行变更都能追溯到用户请求

## 4. 目标驱动
- 将任务转化为可验证目标，而非模糊指令
- 多步骤任务使用计划格式：`1. [步骤] → 验证: [检查方式]`
- 未能通过验证时自主循环修复，而非等待澄清
