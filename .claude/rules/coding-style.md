# 编码规范

## 行为准则

1. **先想再写** — 不确定就问，有歧义呈现多种理解，发现更简单方案主动提出
2. **简单优先** — 不加没要求的功能、抽象、配置项、不可能发生的错误处理。200 行能写 50 行就重写
3. **精准修改** — 只改必须改的，不顺手"优化"周围代码。发现无关死代码只提不删
4. **目标驱动** — 任务转化为可验证目标，验证不过自主修复，不等人喂

## Git

- git 命令用 `git -C <path>` 语法，不用 `cd ... && git ...`
- commit message：中文，格式 `feat: [F001] 功能描述`
- 不使用 git push

## 文件编码

- UTF-8 无 BOM，行尾 CRLF
- .cmd 脚本调用其他 .cmd 必须用 `call` 关键字

## Agent/Command 纯净性

`.claude/agents/` 和 `.claude/commands/` 不得包含项目特定硬编码（路径、构建命令、技术栈、commit 格式等）。这些信息从 CLAUDE.md / rules / memory 获取。判断标准：换到另一个项目还能直接用，说明是纯净的。

## 经验归档

发现重要踩坑或最佳实践时，主动写入 rules（项目特定 → `project-*.md`，通用 → `global-*.md`）。核心约束不要只写 memory——memory 不自动加载。
